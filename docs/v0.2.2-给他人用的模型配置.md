# v0.2.2 — 交给别人用：模型怎么配、还要准备什么

> 对照现状（sidecar 已用 OpenAI Python SDK）与「任何人都能配自己的模型和节点」。日期：2026-08-19。
> 性质：产品约定。本文不改代码；批准后再做设置页与 sidecar 覆盖。

---

## 先把现状说清楚

调用层**已经是** OpenAI 兼容 SDK：

```python
client = OpenAI(base_url=cfg.base_url, api_key=cfg.api_key, timeout=120.0)
client.chat.completions.create(model=cfg.model, messages=..., tools=...)
```

所以「默认支持 OpenAI SDK」不是新造一条供应商通道，是：**凡是 Chat Completions 兼容的节点都能接**（OpenAI、DeepSeek、OpenRouter、部分本地网关）。

今天别人真正配得动的只有 sidecar 仓库根 `.env`：

| 环境变量 | 作用 | 没写时 |
|---|---|---|
| `OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY` | 钥匙 | 不能聊 |
| `OPENAI_BASE_URL` | 节点 | 默认 `https://api.deepseek.com` |
| `MODEL_NAME` | 模型名 | 默认 `deepseek-v4-flash` |
| `PEN_ALLOW_ROOTS` | 允许当教材的目录 | 只认 git 仓根，别人的 vault 会 400 |

**没有 thinking level。** 插件设置页只有 sidecar URL。钥匙刻意不进 vault（`data.json` 会随库 Sync）。

## 别人要「用得好」，还要准备什么

插件三件套（`main.js` / `manifest.json` / `styles.css`）**单独不够用**。点读笔的脑子、钥匙、写盘沙箱都在 sidecar。一份能交给外人的最小包是：

1. **Obsidian 桌面版**（插件 `isDesktopOnly`）。
2. **本机 Python 3.11+**，在仓库里 `pip install -r pen/requirements.txt`。
3. **跑着的 sidecar**：`python -m pen --host 127.0.0.1 --port 8765`。
4. **他自己的钥匙**，写在 sidecar `.env`，不要贴进插件设置。
5. **他自己的节点**：`OPENAI_BASE_URL` + `MODEL_NAME`（或以后在插件里改这两项，见下）。
6. **`PEN_ALLOW_ROOTS=<他的 vault 绝对路径>`**，否则框选自己的笔记会 import 失败。
7. 把插件拷进 `Vault/.obsidian/plugins/socrates-pen/`，关掉 Restricted mode。
8. 一本他想读的笔记（不必是我们的通关手册）。

缺第 3、4、6 步，插件界面再漂亮也只是「连不上 sidecar」或「教材不在允许的根内」。

交给别人时还应附带：`.env.example`、一条启动脚本、设置页里把上面几条写成人话。现在这些还没有。

## 你点名的三项，建议放哪

| 项 | 放插件设置 | 放 sidecar `.env` | 建议 |
|---|---|---|---|
| 模型名 | 适合常改 | 已有 `MODEL_NAME` | **两边都能看，插件改了以这一次请求为准** |
| Base URL | 适合换节点 | 已有 `OPENAI_BASE_URL` | 同上 |
| Thinking level | 适合按场景拧 | **今天没有** | **只放插件 + 请求体**，默认 `off` |
| API key | **不要** | **只放这里** | vault 会 Sync，钥匙进 `data.json` 就漏 |

原则不变：插件是遥控器，sidecar 才碰钥匙。插件把「用哪个模型、打哪个 URL、想得深不深」传给 sidecar；sidecar 用自己的 key 去调 OpenAI SDK。

Thinking 建议四档，对齐 Chat Completions 的 `reasoning_effort`：

| 档 | sidecar 行为 |
|---|---|
| `off`（默认） | 不传 reasoning 字段。普通 chat 模型最稳 |
| `low` / `medium` / `high` | `reasoning_effort=该档`。推理模型（o 系列、部分 DeepSeek thinking）才有意义 |

不支持该字段的节点可能 400。所以默认必须是 `off`，由用户自己打开。DeepSeek thinking 若还需 `extra_body={"thinking":{"type":"enabled"}}`，只在档位不是 `off` 时附加，避免普通模型被多余字段打挂。

## 建议的下一刀（还没做）

1. sidecar `ChatBody`（以及 propose/narrate 若走 LLM）增加可选覆盖：`model`、`base_url`、`thinking`。没传就继续读 `.env`。
2. `GET /v1/health` 的 `llm` 摘要带上当前生效的 model / base_url / thinking（仍不含 key）。
3. 插件设置：Sidecar URL、Model、Base URL、Thinking（下拉 off/low/medium/high）。
4. 每次 `/v1/chat` 带上这三项。钥匙永远不离开 sidecar。
5. 仓库加 `.env.example` 和 `obsidian/README` 的「五分钟外人清单」。

不做：插件内存 key、第二套 Anthropic/Gemini 原生 SDK、账号云同步、帮别人在插件里一键启动 Python。

---

## 和「我们自己用 DeepSeek」怎么共存

自己用：`.env` 里 `DEEPSEEK_API_KEY` + 默认 base/model，thinking 保持 `off`，和现在一样。  
别人用：自己填 OpenAI 或任意兼容节点。产品叙事从「DeepSeek-only 教学笔」变成「OpenAI 兼容的本机笔，默认仍指向 DeepSeek」。
