# v0.1.1 — import 任意路径 + commit 失败漏删提案

> 对照 Kimi K3 交叉审查。只修两个钉出来的洞。日期：2026-08-18。
> 不改手册正文，不开 Q2/Q3，不写 Obsidian 插件。

## 为什么动

1. `POST /v1/handbooks/import` 只检查「是不是文件」。登记成功后，写沙箱跟着扩到那条路径（`assert_write_target` 只比「登记路径」）。本机任意进程可以登记 `~/.zshrc` 再走写回。
2. `/v1/writeback/apply` 在 `apply_insert` 成功之后、`_proposal_del` 之前，若 `git commit` 失败就 400。原文已改、提案还在；再点一次会把同一折叠加第二次。

## 改法

**Import / 登记**

- 只接受 `.md` / `.markdown`。
- 拒绝 `.env`、路径里含 `.git`。
- 文件必须落在允许的根内：默认 `REPO_ROOT`；额外根用 `PEN_ALLOW_ROOTS`（环境变量或 `.env`，`os.pathsep` 分隔）。给以后的 vault 留口，现在默认不能登记库外任意文件。
- `handbook_id` 走与 session 相同的 `_SAFE_ID`，禁止 `..` 逃出 `.pen/libraries/`。
- `apply` / `get_content` 再验一遍路径，旧的毒 meta 也不能读/写。

**Apply + commit**

- `apply_insert` 成功后**一定**删提案，再谈 commit。
- commit 失败改为 **200**：`ok: true`，`commit: null`，`commit_error` 带原因。前端把原因写进气泡，不再当整单失败去重试 apply。

| `pen/tests/test_sandbox.py` `test_app.py` | 拒任意路径；commit 失败不双写 |

## 验收

- pytest：库外 `.md` / 非 md / `.env` / 坏 `handbook_id` → 400 且不落 meta；`PEN_ALLOW_ROOTS` 下 tmp 教材可登记。
- pytest：apply + commit 抛 `GitError` → 原文变长一次、提案消失、HTTP 200 带 `commit_error`、再 apply → 404、原文不再变长。
- Chrome：页面仍能打开默认手册；DevTools 里 POST 非法 import 得 400；不 apply 真手册。
