# v0.12.11 — 闸看得比它自称的窄

v0.12.10 把两条靠人记的约定做成了扫描，方向对。但两个审查 Agent 各自
独立发现：**那两条扫描看得比它自称的窄**，而一条看不全的闸最危险的地方
在于——它报绿的时候你会以为查过了。

三个盲区，全部实测确认，全部修掉。

## ① 三元整条逃逸，而仓库里现在就有一个活例

第一版的正则把 `t().` 锚在 `=` / `(` 后面：

```js
/this\.err\s*\+?=\s*t\(\)\.(\w+)/g
/new Notice\(\s*t\(\)\.(\w+)/g
```

任何插在中间的语法都能把它顶掉。`PenView.ts:1080`：

```ts
new Notice(this.err ? t().noticeSessionArchivedResendFailed : t().noticeSessionArchived);
```

**两个键一个都看不见。** 今天它俩都是 `notice*`，闸没报错不是因为检查通过，
是因为**它压根没看到**——它合规靠的是写的人当时对。而这一行恰恰是 v0.12.7
为了修「Notice 被吞掉」新写的，正是最容易再被改坏的那类代码。

（跨行不是问题：JS 正则的 `\s` 本来就包含 `\n`。这条我担心错了，
审查实测三种跨行写法全部抓得到。）

**改法：别修正则，换个抓法。** 定位和取值拆成两段——先按
`this.err =` / `new Notice(` 切出整条语句，再在**整段右值**里扫所有
`t().key`：

```js
const keysIn = (seg) => [...seg.matchAll(/t\(\)\.(\w+)/g)].map((m) => m[1]);
[...src.matchAll(/this\.err\s*\+?=\s*([^;]*);/g)].flatMap((m) => keysIn(m[1]))
```

三元、模板串、一条语句里多个键并存，全都进来了。

**还抓不到的**（在这个仓库里没出现过，先不管）：别名
（`const s = t(); this.err = s.noticeBad`）、方括号（`t()["noticeBad"]`）、
以及洗过一手的 `:782`（`this.err = t().errNoSelection; new Notice(this.err);`
——那处今天是有意双用，是对的）。

## ③ 键完整性闸把嵌套对象整个跳过——14 条读者可见的文案在视野外

```js
if (typeof v !== "string") continue;   // ← phases 和 chips 就这么没了
```

`phases`（4 条）和 `chips`（5 × label/hint = 10 条）都是**真会显示给读者**
的：后端不下发标签时 `chipLabel()` / `chipHint()` 回落到 `chips.*`，
`phaseText()` 回落到 `phases.*`。前面那些 spot check 只点了「未知 id
照抄后端」「已知 id 本地化」两种，没有一条在扫全集。

改成递归下钻。顺带修了标签上的数字：原来写
「111 个键」是 `Object.keys().length`（89 字符串 + 20 函数 + 2 对象），
而**真正被断言的只有那 89 条**——读的人会以为 111 条都验过了。
现在报的是真数：**103 条**（89 顶层 + 14 嵌套）。

### 递归之后立刻抓到一条我自己写错的断言

递归一开就红了三条：`chips.socratic.hint` / `explain_zero.hint` /
`examples.hint`。查下来它们在**两张表里都是故意留空**的（那三个 chip
本来就没有提示语）。是断言写错了——该守的是
**「zh 非空 ⇒ en 非空」**，不是「en 一律非空」。一刀切会把
「有意不译」误报成「漏译」，而误报多了就没人看闸了。

## 一处用词：「登记**过**笔记」

`errSessionGoneNoHandbook` 的中文原本写「面板上还没有登记**过**笔记」。
「过」是对**历史**的断言，而代码知道的只有**此刻** `handbookId` 是空的。

这两件事今天等价（`handbookId` 从不被清空），但**这条分支存在的全部理由**
恰恰是「将来有人加了『重开面板恢复上次会话』」——到那时读者明明框选过、
面板也恢复出了一场对话，只是 `handbookId` 没跟着恢复。他看到
「还没登记**过**笔记」，第一反应是「我明明登记过」，而这句话正好出现在
他最需要相信面板的时候。

改成「还没有**已登记的**笔记」。英文那边 `yet` 本来就只描述状态，不动。

（这条和这一串审查一直在抓的是同一件事：**断言一个自己并不知道的因由**。
这次是断言了一段自己并不知道的历史。）

## 一条明知有代价、决定接受的

`doApprove()` 那条路上，读者刚点完「同意写回」，最想知道的
「你的笔记没有被改动」排在第 **64–72** 字，前面隔着整整 **53** 个字关于
会话和登记的解释（追加物本身占第 54–74 字）——而且**行动指令排在结果
告知之前**。对比 revive 成功那条
`errApprovalArchived`（「……已经找不到了。**原文没有被改动。**已经给你开了
新的一场」），顺序是对的。

这是 `+=` 机制的固有代价：追加物永远在末尾。**接受，不改**：这条分支
今天不可达，为它破例不值；要修就得给 `doApprove` 单写一条完整句，那是
一份重复文案 + 一处会漂的地方，而 v0.12.8 立的原则正是「追加不是替换」。

**将来真要动的时候，动的是 `errSessionGoneNoHandbook` 在审批语境下的
那条句子（把「没有被改动」提到「请先框选」前面），不是去动 `+=`。**
写在这里，免得将来有人先去动 `+=`。
