# v0.10.3 — 一轮对话拿两份跨书预算（审批续跑）

> 规划 v0.10.x 时扭出来的**既存** bug，不是这一轮改动引入的。
> 日期：2026-08-20。

## 病症

`config.py` 里那句注释是这么写的：

> **一轮对话里**读当前手册以外的文件的总字符预算

但读者点一次「审批这次编辑」，这一轮就拿到了**两份**预算。

## 为什么

审批把一轮劈成两个 HTTP 请求，两边各建一个 ctx：

```
POST /v1/chat          → tutor.stream_chat  → ctx = _tool_ctx(...)   ← 计数器在这里
   （模型提出 edit_file，暂停）
POST /v1/chat/approve  → tutor.resume_chat  → ctx = _tool_ctx(...)   ← 又一个新的，清零
```

跨书预算的计数器（`cross_book_chars` / `cross_book_reads`）就活在这个 dict 里，
不落盘。于是「翻 8 本书 → 提一次编辑 → 被拒 → 再翻 8 本」是可以循环的，
而且**模型自己就能触发暂停**，不需要读者配合。

## 判定是 bug，不是取舍——三条证据

1. `_tool_ctx` 里 `read_ok` 是**特意**从 `session.read_ok_paths` 重建的。
   作者确实想过「暂停期间什么必须活下来」，选了 read_ok，漏了预算。
   **这是遗漏的形状，不是取舍的形状。**
2. 本仓每一处刻意的不对称都带一段注释（`read_roots` 那段、`_shelf_paths`
   那段、`_ripe` 那段）。这里一个字都没有。
3. 可达性不为零，见上。

## 修法

`session.pending` 本来就落盘（sidecar 重启也不丢），把两个计数器冻进去，
`resume_chat` 里恢复。

老会话的 pending 里没有这两个键 → 0 → 与今天完全一致，**不需要迁移**。

## 翻书轮数**故意不跟着修**

同类泄漏，但保留重置，而且**要把理由写进代码注释**——不写的话，下一轮
review 一定会把它当漏网之鱼报上来。

- 跨书预算是「这一轮总共能花多少钱」，审批不该让它翻倍；
- 轮数是「别让一次不受打断的循环跑飞」，而**读者点那一下就是真实的断路器**。

跟着一起清零的话，暂停前用满 100 轮的会话在批准之后第 0 轮就被收口枪顶住，
读者看到的是「批准完师傅答得莫名其妙地敷衍」。
