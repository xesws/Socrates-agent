# v0.12.13 — 下限就是可以静默丢掉的量

v0.12.12 把「闸的闸」从「测自己那份副本」改成了「测真正在执法的那一份」。
方向对，实测也有效——**彻底**把正则写坏确实会红。

但审查追了下一步：**部分写坏是静默的**，因为那条防瞎断言是个**下限**，
而下限定得比真数低一截。

| | 真数 | 上一版的下限 | 富余 |
| --- | --- | --- | --- |
| 文件 | 11 | `>= 3` | 8 |
| err 键 | 7 | `>= 5` | 2 |
| notice 键 | 10 | `>= 3` | **7** |

**富余就是可以静默丢掉的量。** 两个实测出来的例子：

## ① 把 v0.12.12 刚放宽的操作符收回去

`(?:\+|\|\||\?\?)?` 改回空 → `err 6 个`，`6 >= 5` → **57 项全绿**。

丢掉的是全仓**唯一**那条 `+=`，也就是
`PenView.ts:1186  this.err += t().errApprovalUntouched;`
——**v0.12.8 整个版本就是围着它建的**。

复合验证：同一次突变里再把那条 `+=` 改成
`this.err += t().noticeRegisterFirst;`（真违规）→ **仍然全绿**。
执法的看不见它，防瞎的也没吭声。

## ② 把 Notice 那条收回成 v0.12.10 的形状

只认 `new Notice(t().xxx);` → `notice 8 个`，`8 >= 3` → **全绿**。
丢掉的正是 `:782`（`new Notice(this.err)`）和 `:1080`（三元）。

复合验证：再往 `:1080` 的三元里塞一个 `err*` 键 → **仍然全绿**。
**这一整串的起点 bug 原样复活，防瞎闸一个字都没说。**

## 改法：下限钉到今天的真数

```js
const FLOOR = { files: 11, err: 7, notice: 10 };
```

富余全部变成绊线。**维护契约是「只涨不跌」**：合法新增文案会把真数推高，
`>=` 不会误伤；合法删键时手动把这里的数往下调一格——和 `mutate.py` 的
锚点是同一套约定，本来就在维护。

魔数的问题不在于它是魔数，在于**没人知道它离真数还有多远**。写成真数之后
这个距离恒为 0，任何一次「少扫到」都立刻撞线。

## 顺带白捡的一个零宽断言

v0.12.12 把赋值符放宽成 `(?:\+|\|\||\?\?)?=` 之后，`===` 会被误吃：

```
被吃 ⚠  if (this.err === t().noticeX) return;   → 捕获 "== t().noticeX) return"
不吃 ✓  if (this.err !== t().noticeX) return;
不吃 ✓  this.errors = t().noticeX;
```

全仓比较形式今天是 **0** 处（两边独立数过），所以这不是在修现行 bug。
但 `=` 后面加一个 `(?!=)` 是免费的，其余行为一字不变。

**反向验证过它不是空转**：拿掉 `(?!=)`、插一句
`if (this.err === t().noticeRegisterFirst) return;` → 闸**误报**
（`走错槽：noticeRegisterFirst`）；加上就绿。

## 审查顺手查证、结论是「没问题」的两件

- **`/g` 正则提成 const 之后重复用没有 `lastIndex` 残留。** 这是把正则提成
  变量最经典的坑（`.exec()` / `.test()` 会推 `lastIndex`），但
  `String.prototype.matchAll` 按规范是**克隆一份**再迭代。实测同一个
  `ERR_ASSIGN` 连着 `matchAll` 两次都是 3 条，事后 `lastIndex === 0`。
  下一个人再加一处 `matchAll(ERR_ASSIGN)` 是安全的。
- **`walk()` 的新函数检查三种坏法都抓得住**：`en.approvalTarget` 改成
  字符串 / 整条删掉 / 改成对象，三次都红。
