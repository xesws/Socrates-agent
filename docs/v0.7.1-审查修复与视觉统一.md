# v0.7.1 — 审查修复与视觉统一

> 两个独立 review 各跑了一遍 v0.4.3–v0.7.0，抓出 4 个 P0。顺带把字符画的视觉语言统一了。日期：2026-08-20。

## 修掉的真 bug

### 1. `msg` 被局部变量遮蔽，两条后端文案是死代码

`pen/tutor.py` 里 `reply = _create(...)` 原本叫 `msg`，遮蔽了模块级的 `from pen.i18n import msg`。于是 `_agent_loop` 里那两处 `msg("llm.empty_reply", ...)` / `msg("loop.exhausted", ...)` 必然 `TypeError`，被 `app.py` 的 `except Exception` 兜住，用户看到的是笼统的「对话中途出了意外错误」，丢掉了最有诊断价值的那句「模型 X 返回了空正文（已接上 Y）」。

用假 client 复现过：`TypeError: 'FakeMsg' object is not callable`。修完两种语言都能正确产出。

> 同一种坑我在 `app.py` 里修过一次（局部 `msg` → `commit_msg`），却没想到 `tutor.py` 里也有。`settings.ts` 的 `.addText((t) => …)` 是第三例（遮蔽 i18n 的 `t`），本版一并改名。

### 2. 笔记被重命名 → 裸 500 Internal Server Error

`libraries.refresh_if_stale()` 抛的 `FileNotFoundError("原文消失：…")` 在 `_meta_or_404` 里没人接，直接冒成 500。用户在 Obsidian 里重命名或移走一篇已登记的笔记，再回到旧会话提问或点回退，侧栏就显示 `Internal Server Error`——对谁都没有指导性。

现在是 404 + 「原文找不到了：…。笔记可能被改名或移走了，请重新框选一次。」

### 3. `paintLog("force")` 在重画进行中会被吞掉

`paintLog` 在 `this.painting` 时早退，而 `stick` 是进入时算的。于是「用户在助手还在流式时发了一句」——正是 `force` 要解决的场景——反而不会滚到底。

`tool` 事件是 `void this.paintLog()` 且 `paintLog` 每条助手消息都 await 一次 Markdown 渲染，所以只要有点历史，重画很容易还在跑。

改成把意图落到实例字段 `forceStick`，飞行中的循环在收尾时现读。用忠实转写控制流的模拟验证过：修前 `scrollTop=0`（吞掉），修后 `scrollTop=scrollHeight`。

### 4. `/v1/handbooks/import` 没有本地化

这是插件在「用当前选区」时打的**第一个**请求，而它的 `str(exc)` 直接落进错误条。英文用户 vault 路径不被接受时，第一次交互就吃到一整句中文。

## 上游异常的本地化：渐进式，不用一次改完

`sandbox.py` / `libraries.py` / `index.py` / `snapshots.py` 抛的中文异常经 `str(exc)` 变成 detail。要本地化就得改异常设计，但不必一次改完所有抛出点：

```python
def localized(exc, lang):
    key = getattr(exc, "i18n_key", None)
    return msg(str(key), lang, **(getattr(exc, "i18n_args", None) or {})) if key else str(exc)
```

**挂了 key 的查表，没挂的回落中文原文。** 于是可以一条一条补。本版补了 11 条热路径（import / chat / rollback 走的那几条），词表从 23 条到 34 条。

一个中转陷阱：`libraries.register()` 把 `SandboxError` 重新包装成 `RegisterError(str(exc))`，key 在这一步会丢。必须显式带过去。

> 上一版 doc 把这些统称「边缘路径」，**这个说法对 import / chat / rollback 三条不成立**——它们是热路径。`insert.py` 那一批才真是边缘（v0.4.4 之后插件端根本调不到 `propose`/`retarget`/`apply`）。

## 视觉统一：字标改用与肖像同一套密度阶

字标原本是半块字符（`▀▄█`）栅格化的粗体——那是**像素块**风格，跟密度映射出来的肖像不是一种视觉语言，放在一起显得字标过于"现代"。

改成用同一套 8 级密度阶 `" .:sA3G&@"` 渲染 `SOCRATES`（宽 80×6 / 窄 64×5），并**去掉 3D 挤出**：密度字符自带明暗层次，再叠投影只会把笔画糊掉。层次改由色阶拉开——肖像 `--text-muted`，字标 `--text-normal`。

中文标语不再做任何字符渲染，就是一行等宽文字（字重 600 + `0.34em` 字距），靠字距呼应字符画的疏密感。

> 期间做过一版 103 列的中文半块点阵（480px 容器下 7.4px、680px 下 11px，都清楚），验证了「点阵中文不可行」只对窄栏成立。但按「直接写成中文」的要求撤回了——留在这里备查。

## 底色跟着用户的强调色走

开屏区现在坐在一块底色上，底色由 `color-mix` 把 `--interactive-accent` 掺进 `--background-secondary` 得到，**跟着用户在「设置 → 外观 → 强调色」里选的颜色变**。加一道 150° 对角渐变和一圈 18% 强调色的细边。

深浅两主题 × 紫/绿/橙/红/青五种强调色，十种组合全部实测：底色都跟着变，字符画始终清晰。全程零硬编码色值。

`container-type` 在 `.sp-splash` 上，所以 `100cqi` 解析的是内容盒，加 padding 不影响下面字符画的字号反解。

## 宽栏不再"卡得死"

三处上限在宽侧栏下会不必要地限制显示，全部改成相对量：

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `.sp-alert` | `max-height: 5em`（≈3.4 行） | `clamp(5em, 22%, 14em)` |
| `.sp-panel .sp-fold` | `max-height: 240px` 死值 | `flex: 1 1 auto` 吃满面板剩余空间（面板本身有上限） |
| `.sp-quote` | `-webkit-line-clamp: 2` 死值 | 容器查询分档 2 / 4 / 6 行，文本上限 180 → 420 字 |
| `--sp-art-max` | 480px 之后冻结 | 加 680px 档，Logo 继续生长 |

另外 `styles.css` 里那句「上限 560px 时百分比根本不触发」**算反了**：`clamp(120px, 45%, 560px)` 在 1244px 以下的面板上都是 45% 在管。注释已更正。

## 审批 diff 不再静默截断

`old_string` / `new_string` 各截 800 字符且不给任何提示——用户是看着这段决定要不要放行写盘的，静默截断会让他以为自己看全了。现在超长会追加「… 还有 N 个字符没显示」。

## 历史气泡的语言

后端 `ui_messages` 现在多存一个 `chip` id（点芯片时才带）。前端恢复旧会话时用它重查当前语言的 label，旧快照没有这个字段就回落 `text`。这样英文用户重开一篇绑定过的笔记，不会看到自己的历史气泡是中文。

## 前端测试落了盘

上一版 doc 说的「13 项 smoke test」是临时跑的、没有落盘，不构成可复现验证。现在是 `obsidian/scripts/check-i18n.mjs`（17 项），`npm test` 可跑，并**接进了 `npm run build`**——中英表漏用占位符会让构建失败。已验证：故意让 `healthOkFallback` 少收一个参数时 FAIL，还原后通过。

这条洞值得单说：`const en: Dict` 能拦住缺键（TS2741）和多余键（TS2353），但**拦不住带参函数少收一个参数**——TS 允许把 `(a) => x` 赋给 `(a, b) => x`，因为 JS 里忽略多余实参本来就合法。所以补了一个比对两表函数 `length` 的模块级自检。
