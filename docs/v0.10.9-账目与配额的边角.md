# v0.10.9 — 账目与配额的边角（两路审查扭出来的）

> 都不是崩溃级，但每一条都在让读者「看不到自己花的钱」或者「看不懂为什么
> 没反应」。日期：2026-08-21。

## ① 写回那一格的账：算了，但既不落盘也不下发

`propose_fold_md` 往 `session.spend[fold]` 记账，但 `/v1/writeback/propose`
**全程没有 `STORE.save(sess)`**，响应体里也没有 `spend`。

- 前端第三格在写回之后纹丝不动，要等下一轮对话的 `done` 才补——而「花了钱
  看不见」正是 v0.10.0 要解决的问题本身；
- 读者写回完就关 Obsidian、或者 sidecar 重启 ⇒ **这笔账永久丢**。

顺带一个更结构性的问题：这个端点是全仓**唯一不持会话锁却写 `session` 的路径**。
`propose_fold_md` 的注释写着「请求线程独占，没有 probe 那条红线」——不持锁的话
这个前提不成立。

**修**：加锁 + `finally` 里 save + 响应体带上 `spend`。

## ② `/v1/chat/approve` 的 `done` 不带 `spend`

`chat` 那条带了，`approve` 这条没带。文档把 `done` 称作「唯一的自愈通道」，
这条通道在 approve 上是断的：一轮以审批结尾时，`fold` 和 `probe` 两格拿不到
那次自愈（`chat` 格靠 `spend` 事件还是准的）。

前端有 `if (ev.spend)` 守卫，所以不炸，只是慢一拍。

## ③ `led.max_* or config.*` 永远报不出合法的 0

夹紧表明文允许 `probe_max_per_session = 0`（「本场不探」）和
`probe_max_per_window = 0`（「本小时不探」）。但报表写的是
`led.max_per_session or config.PROBE_MAX_PER_SESSION` —— **`or` 把 0 吃掉了**。

后果：读者把配额调成 0 之后，`try_claim` 根本不会被调到（所以快照也永远刷不新），
面板一直显示旧值，「深挖已用满」那条提示也不会亮 —— 读者只看到「深题突然
不来了」，零解释。**这正是那几行注释想根治的病，却在自己身上犯了一次。**

**修**：哨兵从 `0` 换成 `-1`（上限恒 ≥ 0，所以 -1 是干净的「还没探过」）。

## ④ `refund=True` 退次数、退窗口配额，不退 `last_probe_round`

抢不到并发位、起线程失败 ⇒ 一次 LLM 都没打，但冷却照扣。
`probe_every_n_rounds` 拉到 20 时，一次白失败要冻 20 轮。

`refund` 的语义就是「这次不算数」，那就该退干净。

## ⑤ 并发旋钮在多 vault 下方向是反的

`_inflight` 是进程级计数、限额每次现读，于是真实语义是
**「全局在飞数 < 我的限额」**：

```
A 库（限额 8）起了 8 个 → 全局在飞 = 8
B 库（限额 1）想探 → 抢不到
B 库（限额 2）想探 → 抢不到
```

即：**为了省钱把「同时最多几个深挖」调小，反而更容易被另一个 vault 饿死。**
旧的 `BoundedSemaphore` 没有这个反转（容量是共享的）。

这一版**不改行为**（改了要么回到共享容量、要么做 per-vault 记账，都是更大的
改动），但设置页文案必须说清方向，别让读者以为调小是在保护自己。

## ⑥ 孤儿窗口的余量只有 30 秒

默认档：窗口 930 秒，最坏线程寿命 900 秒，**余量 30 秒**。而这 900 秒里还要塞
书架扫盘（登记表 + 逐本读 400 行）、正文摘录、相似度计算。

更要紧的是 `timeout` 传给 httpx 是 **per-read** 的：一个慢吐字节的中转能让
单次尝试远超那个数。撞破窗口 = 真线程还活着就清空 `running` =
**同一场对话两份深挖并行**，也就是 v0.10.2 要修的那件事本身。

**修**：余量从 30 秒提到「窗口的一半」，并把 per-read 这件事写进注释。

## ⑦ `quota_status()` 是死代码，而且读的是模块常量

它读 `config.PROBE_MAX_PER_WINDOW`——正是同文件 `budget()` 的注释点名批评的
那个错。生产环境不可达（`inbox` 内联了正确版本），但有一条测试给错误行为
背了书。**删掉**，别留一个「看起来能用、用了就错」的函数。

## ⑧ `check-limits.mjs` 只比了两张表的数，没比夹紧算法

前端 `Math.round` 后夹，后端先夹后 `int()` 截断。同一个畸形输入两边不一致：

| 输入 | 前端 | 后端 |
| --- | --- | --- |
| `2.6` | 3（四舍五入） | 2（截断） |
| `[5]` | 5 | 默认值 |
| `"0x10"` | 16 | 默认值 |

从插件走不到（`limitsPayload` 发出去的永远是范围内整数），所以不是活 bug。
但两张表就是为了防漂而存在的，只比数不比算法，等于只防了一半。

**修**：前端也改成截断，并让脚本在一组畸形输入上逐个比对两边的结果。
