## 三条线的完整计划（含未开工的 Q2/Q3）

### 主线一 — 演示闭环与会话续命

**目标。** 框选 → socratic → explain_zero（侧栏图和代码能看）→ 写回确认 → 刷新 / 切诊断 / 杀后端，会话和上文都在。

**落地（本轮）。**

1. `.pen/sessions/{sid}.json` 原子写快照（messages + ui_messages + last_anchor + has_substantive）。Kimi 说「JSONL 就够、别上库」——反的是数据库。GET 需要当前态，快照比回放省事；诊断事件仍走已有 `trajectories/*.jsonl`。
2. `SessionStore.get`：RAM 未命中则读盘。`GET /v1/sessions/{id}`。
3. 前端 `localStorage['pen-session:'+handbook_id]`；进书先 GET 再决定要不要 mint。
4. 写回后只重载原文（`reloadContent`），不新建会话。
5. 对话提升到 `App`：切诊断卸掉 `PenPanel` 也不丢气泡。
6. `PenPanel` 与正文共用 `hydrateMermaid`；补侧栏 mermaid / hljs 样式。

**验收。** 同一脚本连跑：框选 → 反问 → 讲透 →（侧栏若有 mermaid 则成图）→ 切诊断再回来气泡还在 → 刷新后续得上 → 杀后端再问，模型仍记得上文。

### 主线二 — 诊断从计数到掌握度（Q2，本轮不做）

**目标。** 同一坐下的连问归并；writeback 进轨迹；atom 状态机：未探索 → 问过 → 追问中 → 讲通过 → 已沉淀。`narrate` 读状态表。

**落地（下轮）。** 同 session + 同 atom、间隔 &lt; ~1800s 并成一次学习事件；propose/apply/rollback 写 jsonl；从未触碰的 Q 进「未探索」，不算弱。构造四场景验收。不做 Anki、不做分数。

**为何不塞进本轮。** 演示路径会制造假短板，但这不挡「给人看」；状态机要吃本轮刚接上的会话脊梁。先把盘落稳。

### 主线三 — 写回安全与服务韧性

**本轮只做两块（压在演示上）：**

- 提案落盘 `.pen/proposals/{id}.json`，RAM 写穿；重启后仍能 apply。
- search：HTTP **200 SSE**，人话说明 P2 才开放；**不**改 session、**不**写 jsonl。前端芯片仍 disabled。T21 改认 200 + jsonl 不变。

**Q3（本轮不做）：** apply 前对 mtime/行数，漂了用索引重定位，重算不出就拒；rollback 按 proposal 撤销；工具循环加总时长墙，超限收尾成文。不动 `insert.py` 校验 / diff / `gitops.commit`，不上向量检索。
