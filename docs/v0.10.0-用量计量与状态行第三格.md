# v0.10.0 — 用量计量与状态行第三格

> 读者的话：「说到 cost，我们目前应该还没有实时计算 cost 的功能，这个必须得做，
> 这样用户才能实时看到目前花了多少钱。」
> 日期：2026-08-20。这是 v0.10.x「用量看得见，旋钮拧得动」的第一版。

## 读者拍板的两条前提

**① 只数 token，不折算货币。** 三条理由，都不是「没做完」：

- 第三方兼容端点的单价不可靠（同一个 model 名在不同中转价差几倍），而且会过时；
- 缓存命中价差十倍，命中率逐轮抖动；
- OpenAI SDK 默认 `max_retries=2`，**重发那次的 usage 我们根本拿不到**
  （`config.py:68` 早就点过这件事）。

三条叠起来，乘出来的钱必然是假精度。token 至少是供应商亲口报的数。

**② 状态行三格**：`上下文 12.4k · 回复 0.8k · 本会话 128k`。
前两格保持现有语义（此刻窗口占用，诊断用），第三格才是花费。悬停展开分项。

后台深挖恰恰是**读者唯一看不见的花钱路径**，而它一个 token 都没记。

## 「最后一枪」不是 bug，不许改

`tutor.py:184` 的 `usage_snapshot` + `tutor.py:330` 的 `usage.update(...)` 是
**覆盖不是累加**，`docs/v0.1.3` 明写这是设计决定，`test_tutor.py:51-64` 有一条
测试专门锁死「不是求和」。

所以本版**新增**独立累加器，`usage_snapshot` 一个字符不改：

```
usage_snapshot  = 最后一枪的快照，答「此刻窗口占多大」（诊断用）
meter           = 累加器，答「花了多少」（花费用）
```

**键名刻意不一样**（`in_tokens/out_tokens/cached_tokens/reasoning_tokens/calls`
vs `prompt_tokens/completion_tokens/context_tokens`）：将来谁写出 `{**usage, **spend}`，
得到的是一个 9 键的怪东西而不是一个静默算错的 3 键字典。这条不变量有测试守着。

## 账分两处落，永不交叉

- **主对话 + 写回 → `PenSession.spend`**（按 chat/fold/probe 分格）
  外加 `turn_spend`（本轮已花，跨审批暂停仍然有效——一轮从 `/v1/chat` 开始，
  到 `/v1/chat/approve` 那一枪结束，中间隔着两个 HTTP 请求和一次落盘）。
- **深挖 → `SessionLedger.spend`**。

**红线**：后台 probe 线程绝不碰 `PenSession`——它一 `STORE.save(sess)` 就和
主线程的 `messages.append` 抢同一个 `to_dict()` 快照，后写的赢，丢一整轮对话。

深挖那格**不新增写入口**，搭 `add_questions` / `release` 现有的那次 `save`：
多一个 load-modify-save 就多一个和 `add_questions` 的竞态窗口。`Meter` 建在
`try` 外面，两条出口都带上——炸在第二枪时第一枪的钱已经花掉了，不记就永远对不上。

`diagnose.narrate` **不落盘**：它按 handbook 索引，没有会话可挂。放进 HTTP
响应体，谁想看谁看。**这一格不进「本会话累计」**——写在这里免得将来有人发现数对不上。

## 实时性

**主对话走 SSE 新事件** `{"type":"spend", "turn":…, "chat":…}`，
每轮 LLM 调用刚花完钱就报。协议双向安全、不需要版本协商：`api.ts` 的 `readSse`
是通用分发，新 type 落进前端 if/else 链尾部被静默忽略。

**深挖走 `/deep` 轮询，不另开通道。** 直觉上「轮询只在 `deep_running` 时启动、
`running` 一空就停」像是承载不了实时，但**深挖花钱的窗口恰好就是 `running`
非空的窗口**。而且 `add_questions()` 把 `led.spend` 的更新和 `led.running` 的
清空写在**同一次 `save`** 里——看到 `running: []` 那一拍读到的 `spend` 必然是终值。

剩下的缺口由下一轮 `done` 的 `_merged_spend` 自愈（最多晚 3 秒、读者关面板、
探索超过前端 480 秒的轮询预算）。

## 状态行：忙的时候也得看得见

现在 `setStatus` 是 `this.busy ? this.status : ...`——**忙的时候用量整行被阶段
文案顶掉**。而实时计量最有价值的时刻恰恰是忙的时候：看着数字往上爬，是失控循环
唯一看得见的信号。所以忙的分支要挂一个尾巴：

```
忙 → 师傅在想… · 本轮 3.2k
闲 → 上下文 12.4k · 回复 0.8k · 本会话 128k [· 深挖已用满]
```

用 `deepNote` 那个「· 后缀」的现成先例，三条路径都只写同一个文本节点。
**绝不能在这条路径上调 `paintBar()`**——token 事件每 48 字符来一次。
tooltip 只在闲下来时重设（`setTooltip` 会建 DOM）。

数字格式从 `Intl.NumberFormat`（`12,400`）换成紧凑的 `12.4k`：三格加 `deepNote`
在 300px 窄栏必然溢出。

## 不做

- 不折算货币（读者拍板）。
- 不动 `usage_snapshot` 的语义。
- 不改四个 client 的 `max_retries`——那是行为改变，且与后续版本的「默认 = 现状」
  验收冲突。**本版只是把它从「隐形花钱」变成「统计已知偏低」**，如实记在这里。
- `web/src/pen/PenPanel.tsx` 只吃 done 里的 `spend`，**不接 `spend` 事件**：
  它的 `usage` 是 React state，setState 会重渲整个面板，而 spend 事件的频率
  和 token 事件同阶。这是有意的不对称，不是漏了。
