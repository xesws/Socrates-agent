# v0.10.7 — 设置页：常用 + 高级（折叠）

> 读者拍板：「分『常用』和『高级』两区，高级默认折叠。」日期：2026-08-20。
> 这是 v0.10.x 的收尾：**前面六版把每个旋钮的后端语义都跑通了，这一版才把
> 它们放上界面。**

## 排序原则（前六版一直在守）

**每个旋钮上界面时，它的后端语义必须已经在跑。**

绝不出现「界面上能填、填了没反应」的死旋钮——那是 `config.py` 里那条禁令
（「摆一个常量而代码不读它，改的人会以为改了有用」）的界面版，**比常量更糟**：
常量至少读者看不见。

`test_every_limit_is_actually_read_somewhere` 机械地守着这条。

## 折叠用 `<details>`，不用 toggle + 重画

`this.display()` 重画会违背本仓设置页的规矩③（只有语言那一项才重画），
而且会把**正在编辑的数字输入框的焦点和光标位置**一起吃掉。
`Setting` 能挂到任意 HTMLElement，`createEl("details")` 是纯 DOM、零状态、零重画。

展开状态不落盘 = 每次进设置页默认折叠，正是读者要的。

## 控件用 `addText` + `inputEl.type = "number"`，不用 `addSlider`

- `cross_book_chars` 是 0–400000，滑块上根本点不准 24000；
- 精确值必须能敲。

本仓从没用过 `addSlider`（新 API 面），但**已经在摸 `inputEl`**
（API Key 那项的 `c.inputEl.type = "password"`），所以这条是家法。

## 两条容易写错的细节

**空串必须走默认。** `Number("")` 是 0 且 `isFinite`，直接判会把「清空输入框」
变成「把上限设成 0」——而跨书那两项设成 0 就是彻底不翻别的书了。

**clamp 当场夹但不边打字边回写。** 边打边夹会让「1」在你打到「150」之前
就跳成 min，输入框会跟人打架。失焦时才把真正存下的值显回去。

## TS 侧键名用 snake_case

破一次驼峰规约，换掉一张「camelCase ↔ snake_case」映射表——那张表就是
下一次「两个闸不同源」的入口。

## `limitsPayload` 只发改过的字段

全默认时返回 `undefined`，请求体里连 `limits` 这个键都不出现。
这是让「上线当天逐字节一致」从口号变成**可断言事实**的唯一办法：

```
limitsPayload(DEFAULT_SETTINGS) === undefined
⇒ 一个数都没动的老读者，请求体逐字节不变
```

顺带让服务端将来能改默认值，而不被老客户端的全量 payload 钉死。

## 新增 `scripts/check-limits.mjs`

TS 的 `LIMIT_SPEC` 和 Python 的 `LIMIT_RANGE` + 默认常量是**同一道闸的两个
副本**——这是整个 v0.10.x 里唯一新造出来的「两个闸不同源」，而它恰好能用
四十行脚本机械守住。挂进 `npm test`。

后端仍然是权威（它无论如何都会再夹一遍）；前端这张表只管 UX。但漂了就
意味着「界面让你填 900，实际生效 300」，读者查不出来。

## 三句必须写进说明文字的诚实话

1. **主对话那个上限不是硬上限**：到线之后师傅还会用手上的材料出一次答案，
   那一枪不受限。假装是硬上限，读者第一次看到实际花销超出就再也不信了。
2. **「每次深挖最多存几条」调大主要是在增大丢弃堆**：`MAX_RELEASE_PER_TURN = 1`
   封顶了整条链路，每轮仍然只放出 1 条，攒过 6 轮就丢。
3. **「深挖单次调用超时」调大之后**，深挖可能跑到读者当轮看不见结果；
   题不会丢，会在下一轮搭便车抛出来。
