# v0.1.2 — 用户主动新开会话（切断模型上下文）

> 对照「换框选不断上下文；要切断就换 session_id」。日期：2026-08-18。
> 轻量：不按框选切线程，不删旧 JSON，不改诊断。

## 为什么动

一本手册一条滚雪球 session。换框选会把上一处的 `[来源]` 包继续喂给模型。这是有意的同题连问。跨题串话时，用户需要一个明确的「忘掉上一场」。

不用换选当开关。用户点「新开会话」→ 新 `session_id` → 指针改到新会话。旧场不再被 GET-resume 用到。

## 行为

- 换框选：仍同一 session，模型上下文继续 append。
- 点「新开会话」：确认后 `POST /v1/sessions`（不带旧 id）→ 新 UUID。
- `localStorage['pen-session:'+handbook_id]` 改成新 id。
- 侧栏气泡清空；`has_substantive` 归零。
- **当前框选保留**（还在看这一段，只是师傅不记得上一场）。
- 旧 `.pen/sessions/{old}.json` 留在盘上，不删。旧 GET 仍 200，只是 UI 不再指向它。
- 刷新：续的是新 id，空气泡。
- 写回对着新 session 的光标；未再问过则没有 `last_assistant`。

## 验收

- pytest：新 mint ≠ 旧 id；旧 GET 200。
- Chrome：有气泡时点新开会话 → 确认 → 气泡空、localStorage 换 id → 刷新仍是新 id、旧 GET 仍 200。不 apply 真手册。

## 不做
