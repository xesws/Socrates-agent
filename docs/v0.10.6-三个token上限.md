# v0.10.6 — 三个 token 上限

> 读者要的「cost budget（单项任务的花费上限）」。因为拍板了不折算货币，
> 上限就以 token 计。日期：2026-08-20。

## 拍板过的三条

- **分类不分总**：主对话每轮 / 单次深挖 / 跨书翻阅各一个数，超了只停该类。
  不会因为后台深挖超支，把读者正在读的那轮主对话也掐了。
- **默认全部 0 = 不限**，要自己填才生效。所以上线当天行为与 v0.10.5 一致。
- **超限不报错**，照 `tools_impl` 那个现成先例：返回一句让模型收敛的话，
  `ok: True`。硬报错会诱发模型换个参数重试，反而更贵。

`over(spent, cap, headroom)` 里 `cap > 0` 这一半就是「0 = 不限」的**全部**实现。
别改成别的判据——它是「默认档逐字节一致」这条承诺的唯一实现点。

## 主对话：break 到收口枪，但**必须留余量**

超限时跳出工具循环，走现成的收口路径（不带 tools，一枪出答案）。
替代方案都更差：直接返回 → 读者花了钱一个字没拿到（此刻 messages 末尾是
纯 tool_calls，content 是空的）；硬报错 → 正是上面那条先例要避免的。

**但卡在线上的话，上限根本不是上限。** 用本仓自己的实测数
（`config.py` 里记着：一句「另一本讲什么」触发 21 次 read_file、末轮 prompt
27k token）：累计花销是**二次增长**的，每轮把整段 messages 重发一遍。
而收口枪的大小和上限之间**没有任何关系**——它只和 messages 有多长有关。
填 30k 实际会花到约 75k。

余量取 `usage["prompt_tokens"]`——**代码已经在测这个数了**，它就是
「此刻喂进去的上下文」。同样的数字，超出量从 2.5× 降到 1.4×，
而且被「一轮之内新增的内容」封住，不再和 messages 总长挂钩。

两个免费的好处：

- `_step == 0` 时 `0 + 0 >= cap` 对任何 `cap > 0` 都是 False，所以
  **上限永远不会让第一枪打不出去**。填错一个小数字最坏是退化成单轮直答，
  不是把插件变砖。公式自带这个性质，不需要写特例。
- 判据读 `session.turn_spend` 而不是闭包 meter，所以**跨审批暂停仍然成立**。

### 必须诚实标注

**这不是硬上限。** 收口那一枪本身不受限——不打它就等于把已花的钱全扔了。
设置页文案要直说：「这个数是工具循环的预算。到线之后师傅还会用手上的材料
出一次答案，那一次不受限。」假装是硬上限，读者第一次看到 43k vs 30k
就再也不信这个功能了。

### 收口话术要换一句

复用 `FORCE_ANSWER`（「工具次数用完了」）是**撒谎**——次数没用完，是钱到线了。
新加 `FORCE_ANSWER_BUDGET`，措辞对齐跨书那道闸的现成先例，
让两道闸给模型的心智模型一致。

## 单次深挖：第二枪之前被拦下，**不许丢掉第一枪的产出**

第一枪已经花掉了，它产出的 questions 是合法产出。因为「读了一段正文」
反而全丢，那会让「省钱」变成「白花钱」。

但 `excerpt` / `spans` 必须传空：那几条题是模型**看到正文之前**写的，
里面任何跨书行号都是编的，走 `validate_slots` 的「没读过就写行号 = 编」
那条正好筛掉。

新理由 `token-budget`，和已有的 `budget`（数次数）区分开。

## 跨书翻阅：**第三道闸，不替换前两道，而且不改那一行**

跨书读到的内容进了 `session.messages` 之后每轮重发，真实代价 ≈
`字符数 × 剩余轮数`。基于这个：

- 字符闸是**前置**的（文本进 context 之前就拦住）；
- token 闸只能是**后置**的（要等下一次调用回来才知道那段文本值多少 token，
  而那时它已经付过至少一次钱了）。

所以 token 闸回答的是前两道回答不了的问题——**「这一轮已经烧到 X 了，
别再开新书」**，正是掐住那个复利的杠杆：在第 30 轮拒绝打开第 4 本书。

实现上加成一个**独立的前置 `if`**，不给现有条件加第三个子句：
两道闸给模型两句不同的话（看 trace 就知道是哪道触发的）；
`cap == 0` 时由 `over()` 的定义恒假，行为可证不变；变异表那条逐字锚点少改一次。
