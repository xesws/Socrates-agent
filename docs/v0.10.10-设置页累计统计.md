## 数据早就在盘上，只是没人聚合

```
.pen/sessions/<sid>.json          → spend.chat / spend.fold
.pen/probes/sessions/<sid>.json   → spend（深挖那一格）
.pen/probes/<hid>/quota.json      → 只有次数没有 token，另算
```

状态行第三格答的是「**这一场**烧了多少」，设置页那块答的是「**一共**烧了多少」。
两个口径，都得有。

## `GET /v1/usage`

遍历上面两个目录做 `meter.merge` 求和，返回一本 `SpendBook`（形状复用现成的
`TokenRow`，前端类型已经有了）。

三条要注意的：

- **绝不取 `STORE.lock_for()`**。老规矩：那把锁在 `/v1/chat` 整个请求期间
  持有，抢它会把读者下一次提问顶成 409。这里只读文件。
- **`diagnose.narrate` 那格按设计不进累计**（它按 handbook 索引，没有会话可挂，
  只在自己的响应体里）。做统计时别把它算进来，否则数会对不上——
  这条 v0.10.0 就写明过。
- 会话文件可能有几百个。**读坏一个不能让整个统计挂掉**，逐个 try 吞掉。
  同时把「数了几个会话」一起报出去，读者才知道这个数覆盖了多少。

## 设置页那一块

`display()` 是同步的，所以先把 DOM 建出来占位，再异步拉一次填进去——
**不能同步阻塞 `display()`**，sidecar 没起来的时候设置页就打不开了。

拉不到就显示一句「连不上 sidecar」，不要留一片空白让读者以为是零。

顺带把 `quota_status()` 用上：它的 docstring 从一开始就写着「给设置页看的」，
而设置页一直没有统计块，所以它当了很久的死代码。v0.10.9 把它读模块常量
那个错修掉了，这一版让它真正有调用方。
