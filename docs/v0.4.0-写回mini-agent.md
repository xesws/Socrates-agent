# v0.4.0 — 写回走 mini-agent：registry + edit_file + 审批

> 机械按行插入会打乱小标题（模型不知道 section 从哪起，可能自己写一个大标题）。写回必须由模型用 `edit_file` 精确替换。日期：2026-08-20。

## 为什么不走 insert.py

`insert.py` 只增不删、位置由 `HandbookIndex.locate` / 行号决定。模型只负责折叠块正文。小标题层级因此会乱。v0.4.0 把「插哪、换哪、换成什么」全部交给模型。

## SDK（`pen/agent/`）

轻量、不引入 bash / write_file。

| 模块 | 职责 |
|---|---|
| `registry.py` | `TOOLS` 花名册：schema + handler；`schemas()` 发给模型；`dispatch(name, args, ctx)` |
| `permissions.py` | `read_file` → allow；`edit_file` → ask；其余 deny |
| `tools_impl.py` | `read_file` 走现有沙箱；`edit_file` 只改登记的 `original_path`，`old_string` 必须恰好一次 |

`tutor.py` 只做 Pen 循环：调 `schemas()` / `decide()` / `dispatch()`，遇到 ask 把单子放进 `session.pending`，SSE `type=approval` 暂停。

## 循环与审批

1. `POST /v1/chat` 带 `tools=schemas()`。
2. `read_file` 自动执行并回填。
3. 第一个 `edit_file` 不执行：写 `session.pending`，SSE 暂停。有 pending 时再 chat → 400。
4. `POST /v1/chat/approve` `{session_id, pending_id, allow}`：允许则 dispatch；拒绝则回填「原文没动」。然后继续模型循环（可能再次 pause）。
5. 写盘前快照 `pre-edit`；插件「撤销刚才写入」仍走 snapshots。

## 插件

写回芯片走普通 chat，不再 `propose`。侧栏展示 old/new，点「允许这次编辑」才写盘。重载后 `GET /v1/sessions` 带回 pending。

## 不做

- 不注册 `write_file`、`bash`
- 不让模型改非登记路径
- 不把 git 仓库里的通关手册当验收原文（用测试库草稿笔记）
