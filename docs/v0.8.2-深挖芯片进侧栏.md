# v0.8.2 — 深挖芯片进侧栏

> 双层机制收尾。v0.8.1 的深题只落在 probe_store 里，侧栏还看不到，这一版接上。日期：2026-08-20。

## 呈现

按读者定的：**混进底部相关问题列表，带标记，排在最前**。不新开界面概念。

- 深题挂 `is-dyn is-deep`，比实时层的幽灵按钮多一道 accent 描边和一个 `◆` 前缀
- 排序 `dynRank`：deep 在前，quick 在后。深题是「跳出来」的问题，最容易被忽略，沉到底下等于没有
- tooltip 挂 `why`（模型给的「为什么现在该问这个」），读者能看见它为什么冒出来
- **open 题不做任何标注**——读者明确选的。诚实落在回答那一刻：后端已在 v0.8.1 于 `[意图]` 段注入「凭记忆讲，别编版本号」，不影响按钮外观

## 轮询

`GET /v1/sessions/{sid}/deep?since=N`，2.5 秒一拍。用现有 `paintGen` 同款的**代号模式**作废，不用 `setInterval`——代号能在切笔记的一瞬间让在途的那一拍自己早退。

五个终止条件，缺一不可：

| 条件 | 为什么 |
| --- | --- |
| `running` 为空 | 正常路径，也是 sidecar 重启后的路径（返回 `200 {running: []}`） |
| 超过 90 秒 | 硬上限，防止服务端状态卡住时无限轮询 |
| HTTP 404 | 会话没了 |
| 连续失败 3 次 | sidecar 连不上 |
| `!this.els` | 视图已关 |

生命周期清理：`onClose` / `adopt` / `newSession` / 切笔记各作废一次，外加 `registerInterval` 兜底（Component 卸载时框架强制清）。

**新一轮 `send()` 不停轮询**——已经花掉的 credit 不浪费，服务端会按新锚点重判时机。

## 开关

设置页加 `deepQuestions`（默认开）。关掉后前端不轮询，且 `ChatBody.deep=false` 让后端也不起线程——两边都要断，否则关了开关后台还在烧钱。

不加「扫整个 vault」开关：v0.8.1 的默认已经收窄到同目录兄弟 + 仍存在的已登记手册，递归整库会把读者的私人笔记大纲塞进 prompt，跟「数据不出 .pen」冲突。真需要时再单独做，别默认打开。

## 验收

三条对抗剧本：
1. 提问后立刻切笔记再回来 —— 轮询已停、无泄漏、深题从 `getSession` 回来
2. probe 跑着时杀 sidecar 再重启 —— 前端 90 秒内自停，不刷错误条
3. probe 跑着时再问一轮 —— 不 409、不重复起 probe、第一轮结果按新锚点重判后落地
