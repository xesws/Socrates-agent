# v0.8.1 — 异步深挖 probe

> 双层机制的第二步。纯后端，前端不动，可离线单测。v0.8.2 才把深题接进侧栏。日期：2026-08-20。

## 为什么还要一层

v0.8.0 把实时层的占位符、导航、复读挡住了，但没动它的**产出机制**——那些追问仍然是主回复末尾搭车写出来的两行。搭车的两个天花板拆不掉：

1. **没有独立的注意力。** 模型的预算全在正文上。
2. **看的材料是错的。** packet 里的 `[邻域]` 是 4000 字符的选区上下文，而这本手册的邻域里全是它自带的入门题（`Q2. heredoc 里 <<'EOF' 的引号起什么作用？`）。**模型盯着这些题，产出同构题是必然的——这才是「echo 加不加引号」的真正病根**，不是 prompt 没写清楚。

所以深层要**另起一次调用**，而且**故意不喂邻域**。

## 送达通道：会话级收件箱

不延长 SSE 流。`send()` 的 `busy=false` 在 `finally`，延长 N 秒 = 输入框和所有芯片多禁用 N 秒，且 `done` 分支不调 `paint*()`，状态行会卡在「在写…」骗人。

最初设计的是 `done` 带 `probe_id` + 按 id 轮询，**放弃了**，因为键选错：探索期间用户又发一轮就要维护一组 in-flight id；视图关闭再打开 id 就丢了；sidecar 重启返回 404，而 404 也可能是 id 拼错，前端分不清该停还是该重试；`later` 类问题更是无处安放。

改用**会话为键**：

```
POST /v1/chat ──SSE──> done{ dynamic_chips, dyn_chips, deep_running }
                        └─ done 那一刻起 daemon 线程（冻结 job，不持锁）
GET /v1/sessions/{sid}/deep?since=N -> { items, cursor, running, budget }
```

一个游标解决全部场景：切笔记清一次；重开视图 `getSession` 带回来；sidecar 重启返回 `200 {running: []}`，语义明确「没有在跑的，停」。

**双通道**：`timing=="now"` 且过闸 → 轮询捞到当场冒出；`timing=="later"` → 留在池子里，**每轮 chat 重新过一遍成熟度闸门**，成熟了搭便车下发，零额外往返。

### 两条红线

- **探索线程绝不碰 `PenSession`。** 它一旦 `STORE.save(sess)` 就会和请求线程的 `messages.append` 抢同一个 `to_dict()` 快照，后写的赢 → 丢一整轮对话。深题只进 `probe_store`。
- **轮询端点绝不取 `STORE.lock_for()`。** 那把锁在 `/v1/chat` 整个请求期间持有，去抢会把读者下一次提问顶成 409。

用 `threading.Thread(daemon=True)` + `BoundedSemaphore`，不用 `ThreadPoolExecutor`——后者注册了 atexit join，一个卡在 30 秒调用上的 worker 会让 Ctrl-C 停 30 秒。

## 探索算法：最多 2 次调用，永不给 tools

**永不给 tools 是结构性的成本保证，不是自律。** `MAX_TOOL_ROUNDS = 50` 且无 token 预算、无时长墙（作者自己把「工具循环墙」列进了 Q3）。后台任务一旦能自主循环调工具，读者看不见它在烧钱——这是最坏的成本泄漏。

但「定向读 1-2 段正文」是需要的，所以**读由 Python 执行，不由模型自主循环**：

```
第 1 次调用（无 tools）→ 候选问题 + 可选 need_read:[{start,end}]
   ├─ need_read 空 → 直接过滤落地（多数情况，1 次调用）
   └─ 非空 → Python 用 readtool.read_file_report 读，硬上限 2 段 × 80 行
第 2 次调用（无 tools）→ 带正文定稿
```

**广度由代码封死，不由模型自律。**

### 喂什么（故意不喂三样）

不喂 `neighborhood()` 原文（病根）、不喂 `session.messages` 全量历史（含 reasoning_content，会把注意力拉回细节且 token 翻倍）、不喂手册正文（640KB，一次都不读）。

喂：全书目录 87 条全量、全书 Q 清单 80 道、**师傅刚讲的话且剥掉代码块**（`echo`/引号那些废问题就是从代码块里抠出来的）、锚点与读者原话、`diagnose.aggregate()` 的轨迹摘要、七处「第三拍 · 出身」白名单、已问过的。

**前缀缓存是免费的**：目录 + Q 清单对同一本书永远一样，放进 system message 尾部，变量全放 user message。

## 质量：强制填槽 + 确定性校验

不写「要有深度」，写成模型必须填的槽，用代码验。判据的本质：**好问题一定把当前这段和「第二样东西」接上；坏问题只在框选这一段内部打转。**

| 轴 | 必填槽位 | 代码怎么验 |
| --- | --- | --- |
| `bridge` | `anchors` ≥2 且分属不同 Level | `len({a.level}) >= 2` |
| `tradeoff` | `alt` | 非空 |
| `vs_real` | `anchors` 至少一条落在某关「第三拍」 | `locate(start).beat.startswith("第三拍")` |
| `failure` | `trigger` | 非空 |
| `altitude` | `anchors` ≥1 合法 | `locate()` 通过 |

外加：**锚点必须真实存在**（行号在范围内且 `locate(start).level` 与声称的一致）、**引用必须真在那几行里**（题干中反引号包起来的 token 字面出现在 anchors 区间内）。

「`echo` 加不加引号」**填不出任何一个槽**。质量判据从形容词变成了 schema。

**最薄的一环**：能挡编造行号，**挡不住编造 `alt`**。只能靠 prompt 和事后点击率兜。

### 七处「第三拍 · 出身」是确定性可查的

```
Level 0 L193 真实框架里的 Bash        Level 4 L7779  Claude Code 的工具 schema
Level 1 L1701 为什么是 Python          Level 5 L9540  Agent SDK 的 permission 体系
Level 2 L3196 OpenAI 兼容协议          Level 6 L11120 Claude Code 的四档权限
Level 3 L5407 mini-swe-agent 100 行核心
```

这让「跟真实系统对比」这条轴有了合法锚点白名单。读者举的「runtime 层面我们跟 Claude Code CLI 的差距」因此能被逼成有出处的形式，不用联网。

## 时机：模型只有否决权

`timing` 省一次调用，但降格为建议——时机的主要信息源是确定性、零成本的轨迹信号，模型看不到，且对自己刚生成的东西有系统性乐观偏置。

```
模型说 later → 直接 later
模型说 now   → 还要过确定性闸门；不过 → 降级 later
```
**闸门只能把 now 降成 later，永远不能把 later 升成 now。**

## 触发

读者选了「每轮实质回复都探」，所以**不设轮次冷却**。兜底是非降频的：排除 search / 审批中 / 本轮失败 / **writeback 场景**（那些「要不要一起替换占位块」在写回时本身没错，只是不是学习问题，治法是不在那个场景触发）；积压 ≥3 条未抛出时跳过；硬顶每会话 8 次、每手册每天 40 次、进程并发 2。

**不照搬 `is_curriculum()`**：它的 `_SKIP_LEVELS` 含「开篇」，而真人的 11 条有机记录全部落在封面和开篇——照搬会让功能一次都不触发。只排除「封面」和「附录」。

## 验收

- 结构性成本测试：kwargs 里不能有 `tools`；create 调用次数 ≤2；读取次数 ≤2；预算耗尽不发请求；**monkeypatch `STORE.save` 断言探索线程从未调用它**
- 干跑断言 prompt **不含邻域原文**（回归防线）
- 轮询端点在流式期间仍 200（不吃锁）
