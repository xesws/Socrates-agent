# v0.12.4 — 会话按时间清理

> 读者：「日志最多保存最近 7 天的会话吧，每次启动插件的时候都要自动清理一下，
> 不然用户的电脑就直接爆炸了。」
> 日期：2026-08-21。

## 之前是什么样

| 存储 | 有上限吗 | 实测 |
| --- | --- | --- |
| 快照 / 写回提案 / 深挖配额 | ✅ | 都很小 |
| 学习轨迹 `trajectories/*.jsonl` | ❌ append-only | 812 行 / 448 KB |
| **会话 `sessions/*.json`** | ❌ **完全没有** | **3389 个 / 10.4 MB** |

3389 个里 **3371 个是空的**（只有 system prompt）——每划一次词就建一场，
大部分没等到第一句话就被下一次划词换掉了。真聊过的只有 18 个。

## 两档，不是一档

**纯 7 天规则今天一个都删不掉。** 那 3371 个空会话最老的也才几天，
`-mtime +7` 零命中。所以规则必须分开：

| 类型 | 判据 | 保留 |
| --- | --- | --- |
| 空会话 | `len(messages) <= 1` | **1 天** |
| 聊过的 | 其余 | **7 天** |
| **挂着 `pending` 的** | `pending.id` 非空 | **永不删** |

空的那档留一整天而不是一小时：读者刚打开一篇新笔记 → 建会话 → 还没提问，
这时它就是「空」的（实测最新的空会话建于 6.9 分钟前）。

`pending` 是「读者点了写回、审批弹窗还没结果」。那一场删掉，读者点「同意」
就撞 404，手里已生成的提案当场作废——不管它多老都不碰。

读不出来的文件（截断、手改坏了）按**长**的那档算：宁可多留一周，
也不要因为一次解析失败就把读者聊过的东西删了。

## 两个必须绕开的坑

**glob 用 `*.json` 不要用 `*.json*`。** `_atomic_write` 的临时名是
`<sid>.json.<pid>.<hex>.tmp`——后者会命中另一个 sidecar **正在写**的那个文件。

**只成对删 `probes/sessions/<sid>.json`。** `.pen/probes/<hid>/quota.json` 是按
handbook 索引的每小时配额，和会话没关系，跟着删等于把成本闸门清零。
突变表里专门有一条守这个。

## 挂在哪：两条，不是一条

读者说的「每次启动插件的时候」**按字面做不到**——插件不拉起 sidecar
（`obsidian/src/` 里 `child_process` 零命中）。sidecar 可能已经在后台跑了好几天，
读者重启 Obsidian 时它的 lifespan 早就跑完了。

所以两条都要有：

1. `pen/app.py` 的 `lifespan`（`uvicorn` 那边 `reload=False`，只跑一次）
2. `POST /v1/maintenance/purge`，插件 `onload` fire-and-forget 打一枪

第二条才真的对应读者那句话。它幂等、便宜（实测扫 3389 个文件 0.09 秒），
永不抛；插件那边吞掉所有错——sidecar 没起、端口填错、跨域，一样都不该让
插件加载失败，也不该弹一个读者此刻做不了任何事的通知。

## mtime 不等于「最后用过」

`GET /v1/sessions/{sid}`、`POST /v1/sessions` 的恢复分支、`GET /deep`、
`retarget`、`apply` **全都不 save**。读者天天开面板、每次划词都命中并复用
同一个会话，只要不真发一轮对话，mtime 就冻在最后一次 chat 上——第 7 天被清掉，
下次划词静默换成新会话，历史全丢。

→ 前两条路径上各加一次 `retention.touch()`，把 mtime 的语义改成「最后碰过」。

## 删会话的三个连带伤害，读者拍板一并修

不修的话，这一版就是拿一个 bug 换一个更难受的。

**① `send()` / `doApprove()` 没有 404 兜底。**
全仓只有「用当前选区」和「新开会话」两个按钮会 `createSession`。会话被清掉之后
读者的失败模式是**「输入框能打字，一发就报错，不知道该干什么」**——再点还是
同一个死 sid。
现在 `send()` 撞 404 就换一场新的、重绑 `bindNote`（**不重绑的话下次划同一篇
笔记又会捞回那个死 sid**），然后把刚才那句**原样重发一次**（`revived` 参数守着
只重来一次，不然新会话再撞 404 就成了无限套娃），读者不用重新打字。
`doApprove()` **不重发**——`pending_id` 是那场死会话的，换一场也认不出它；
原文没被改动，所以清掉审批状态、开一场新的、把话说明白就是全部该做的事。

**② `deeppoll` 那条 404 终止条件是死的。**
`deeppoll.ts:67` 判的是 `message.includes("404")`，而 `api.ts` 抛的 detail 是
**本地化**的服务端文案（「会话不存在」/ "unknown session"），一个 "404" 字样
都没有。这条终止条件写了、看着有、其实从来没生效过，一直靠 `fails >= 3` 兜着。

病根是 `api.ts` 抛的是裸 `Error(detail)`，状态码在那一层就丢了。
现在有了零依赖的 `src/apierror.ts`（`ApiError` + `isGone`），
所有调用方查同一个字段——只有一个真相来源。

> 为什么 `ApiError` 单独一个文件而不是塞进 `api.ts`：`deeppoll.ts` 要用它，
> 而 `api.ts` 依赖 `settings.ts` → `obsidian`。deeppoll 一旦顺着这条链走，
> 它就不再是叶子，`check-poll.mjs`（`platform: neutral`，不 external obsidian）
> 当场打不动包。

**③ 提案会变成死提案。** 由 ① 的 `doApprove` 那一半兜住。

## 一个要明说的取舍

`GET /v1/usage`（设置页那块累计统计）**独立 glob 会话目录**，不走 STORE。
删掉过期会话 = 那个数会往下掉。文案里写明了：「只统计还在保留期内的会话
（空会话留 1 天、聊过的留 7 天），所以这个数会随着旧会话被清理而下降。」

顺带修掉 `app.py` 里那个 `version="0.8.6"`——落后十几个版本了，现在是 `0.12.4`。

## 又一份自己骗自己的看门狗

`check-poll.mjs` 里造的 404 是 `new Error("HTTP 404 unknown session")`——
一个产物**永远不会抛**的形状。看门狗和实现各自绿着，中间那条终止条件是死的。

现在它抛真的 `ApiError(404, "会话不存在")`，并且入口改成一段现编的门面
把 `deeppoll` 和 `ApiError` 打进**同一个** bundle——分两次 build 会得到两个
不同的类，`instanceof` 恒假，那就是换一个幻觉。另加两条：
「404 判的是状态码不是文案」和「500 不当成会话没了」。

新增 `check-api.mjs`（14 项）守住 `api.ts` 的错误形状本身：状态码带没带出来、
本地化文案里确实没有 "404"、SSE 那条路（`streamChat` / `streamApprove`）
也抛 `ApiError`、`purgeExpired` 打的是 POST 且尾斜杠不会变双斜杠。

## 已知的局限

`send()` / `doApprove()` 的 404 兜底那段逻辑本身没有自动化测试——
前端没有 DOM 测试框架。它依赖的**前提**（调用方认得出 404）由 `check-api.mjs`
守着，恢复动作本身只有真跑才看得出来。
