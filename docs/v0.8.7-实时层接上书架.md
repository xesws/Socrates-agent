# v0.8.7 — 实时对话接上书架（跨教材只连了异步那半条线）

> 读者直接打字问「我们的另外一本《通关手册》到底在讲什么？跟这本有什么区别？」，
> 师傅答「另一本我没读到，不能瞎编……你把它的路径给我，我去读一眼」。
> 日期：2026-08-20。

## 现象

师傅的回答**在人设上完全正确**——不读就猜是江湖骗子干的事，这条纪律是我们自己定的，
它守住了。问题在于它本来不必猜：书就在同一个 vault 里，工具、沙箱、扫描器全都是通的，
唯独没人把这件事告诉它。

## 根因：书架只接了异步那半条线

四条实测：

| 查什么 | 结果 |
| --- | --- |
| `library_scan.shelf_digest()` 能扫到另一本吗 | **能**。返回 183 字符（标题 + 前 5 条大纲），冷启 1.2ms，命中 TTL 缓存 0.002ms |
| 这段喂给了谁 | **只有 `pen/probe.py:671`**（后台深挖）。`grep shelf_digest` 全仓就这一个生产调用点 |
| 实时对话的 `build_user_packet` 里有书架段吗 | **没有**。`[来源] [全书目录] [框选] [邻域] [意图] [用户补充] [已经抛过的追问]`，七段全是当前这本 |
| `read_file` 能读到 vault 里另一本吗 | **能**。`read_file_report(cur, 另一本, 1, 3)` → `ok=True`，已读出前 3 行 |

`PEN_ALLOW_ROOTS=/Users/tangyiq/dev/socrates-pen-vault` 早就配好了，
`assert_readable` 对另一本手册直接放行。所以师傅**每一轮都握着能读它的工具**，
只是不知道有这么一本书、更不知道路径。

这是 v0.8.1 的设计遗漏：当时「跨教材」这条需求整个挂在 probe 上，
默认深挖才需要看别的书。但读者是**直接开口问**的——那条路径上一个字都没有。

## 第二个洞：`shelf_digest` 不输出路径

现在的行格式是：

```
- 《书名》：一级标题 / 二级 / 三级 …
```

probe 那边靠 `book` 字段点书名、`_shelf_paths()` 反查路径，所以不需要。
但实时层要让师傅自己去 `read_file`，**没有路径它照样读不了**——
只会去猜一个文件名，猜错就退回「你把路径给我」。这两处必须一起补，补一个等于没补。

## 改法

### 1. `library_scan.shelf_digest(..., with_paths=False)`

加一个默认 False 的参数，为真时行格式变成：

```
- 《书名》  path: /绝对/路径.md
  大纲：一级标题 / 二级 / 三级 …
```

**默认值不变**是刻意的：probe 的 system 尾部是前缀缓存区，格式一改缓存全废，
而它并不需要路径。只有实时层传 `True`。

**缓存键要带上这个参数**——`_CACHE` 现在以 `str(current_path)` 为键，
同一本书两种格式会互相污染（先跑 probe 的无路径版，实时层 60 秒内就拿到没路径的那份，
症状是「有时能读有时读不了」，最难查的那类 bug）。

隐私边界**不变**：仍然只列「已登记 且 落在 allow_roots 内」的。
路径本身不是新增暴露面——`[来源]` 段里的 `handbook_path` 早就在送当前手册的绝对路径了。

### 2. `tutor.build_user_packet(..., shelf="")`

新增一段，**只在 shelf 非空时出现**：

```
[工作目录里的其他教材]
（下面只是每本前 400 行扒出来的标题，不是正文。
  要讲它讲了什么，必须先 read_file 按上面的 path 读，读了再说。）
- 《…》  path: …
```

`shelf` 是**传进来的字符串，不在 tutor 里扫盘**——`build_user_packet` 至今是纯函数、
无 IO，被一堆单测直接调，不能因为这个功能给它塞一个会读磁盘的依赖。
扫盘放在 `app.py` 调用点（1.2ms + 60s 缓存）。

只有一本书时 `shelf_digest` 返回空串 → **整段消失**，不写「（无）」。
写「（无）」会让模型以为我们确认过没有别的书；整段消失时它答「我没读到」是**对的**。

### 3. `app.py:590` 调用点扫一次

```python
shelf = library_scan.shelf_digest(path, [m.original_path for m in libraries.list_handbooks()], with_paths=True)
```

包 try/except：登记表烂了不能把正常对话带崩（probe 那边已经是这个写法）。

## 不做的事

- **不自动去读别的书**。师傅想读就调 `read_file`，那是它自己的判断，
  也会在界面上以「在翻手册…」显示出来。后台偷读别的书 = 读者看不见的开销。
- **不递归扫 vault**。「已登记」这道闸是 v0.8.1 花了代价才立的
  （第一版扫同目录 .md 兄弟，实测送出去过《和 A 公司的合同条款》这种标题）。
- **不动 probe 的格式**。它的前缀缓存区一动，重复探索的边际成本就从 1/5 涨回 1。

## 验证

- 单测：`shelf` 为空时 packet 里**不出现**段标题；非空时出现且带 path；
  `with_paths` 两种取值在同一 key 下**不串**（缓存键回归）。
- 真跑：在 `writeback-fixture.md` 上原样重问那句话，
  验收线是师傅**真的调了 `read_file` 去读另一本**（tool 事件里看得到），
  而不是照着大纲吹。
- 既有闸门：`pytest`、`npm run build`、`python -m pen.index --check`。

## 自查时发现的另外两个

### 一、`probe._shelf_paths()` 和书架指向不同的副本

同一本书在仓库根和 vault 各有一份、标题一模一样。`shelf_digest` 现在按「就近 + mtime」
留 vault 那份，但 `_shelf_paths()` 是 `out.setdefault(title, p)`——**先到先得**，
`list_handbooks()` 按目录名排序，`swe-agent-v2` 排在 `vault-swe-agent-v2` 前面，
反查拿到的是仓库根那份（8-13 的旧版），而书架上印的是 vault 那份（8-17）。

模型点名读「《通关手册》第 500 行」，**读到的和它以为在读的不是同一个文件**，
而且读的那份还是过期的。实测：

```
_shelf_paths()                → /Users/tangyiq/dev/Socrates-agent/SWE-Agent通关手册v2.md
shelf_digest(..., True) 印的  → /Users/tangyiq/dev/socrates-pen-vault/SWE-Agent通关手册v2.md
```

改成同一个 `_prefer_nearby` 排序，签名加 `current_path`。两边现在都指向 vault 那份。

### 二、pytest 一直在往真实登记表里写

`test_probe.py` 的 `idx` fixture 打的是 `config.LIBRARIES_DIR`，
而 `libraries.register` 用的是 `libraries.LIBRARIES_DIR`——**模块 import 时绑定的另一个名字**，
patch 落空。真实 `.pen/libraries/` 里 11 本有 4 本是 pytest 留下的死记录
（`probe-fx` / `other-book` / `shelf-in` / `shelf-out`，全指向已被系统清理的
`/private/var/folders/…/pytest-of-tangyiq/`）。

危害不是泄漏（`_within_allowed` 和 `is_file()` 两道都挡得住），是**每次实时对话扫书架
都要把它们遍历一遍**，而且会随每次 pytest 持续累积。`test_libraries.py` 有个
`_isolate_pen()` 三行都打全了，probe 这边少打了一行。

补上那一行后：挪走 4 条死记录 → 跑 `pytest -q` → 登记表**没有重新生成**它们。

## 四路审查（correctness / requirement / cost-privacy / regression）

对抗验证后去重，**四条真缺陷**，其中一条足以让整个功能不成立。

### P1 · 书架的闸比 read_file 的闸宽，印出去的路径师傅读不到

三路独立报了同一条。我的真跑恰好用了 `writeback-fixture-570897b1`
（`allow_root` = vault），**掩盖了这个 bug**。换成仓库根那本：

```
=== swe-agent-v2
  meta.allow_root = None          → 沙箱根只有 /Users/tangyiq/dev/Socrates-agent
  书架印: /Users/tangyiq/dev/socrates-pen-vault/writeback-fixture.md
    read_file → ok=False  拒绝读取…不在本手册允许的根内
```

书架的可见性走 `handbook_allow_roots()`（REPO_ROOT + `PEN_ALLOW_ROOTS`，全局），
而 `read_file` 走 `assert_readable(original_path, extra_roots)`（**每本手册自己的根**）。
**两套根。** 师傅照着书架去读，撞在沙箱上——读者看到的是一次白跑的工具调用加一句道歉。
印一条读不到的路径比不印更糟。

probe 那条线同病：`_shelf_paths()` 用全局闸列书，`_read_excerpts` 用
`job.extra_roots or [REPO_ROOT]` 去读。模型点名读别本，静默落空，
它以为引了别的教材，实际什么都没读到。

**根治**：`pen/sandbox.py` 新增 `reading_roots()`，`assert_readable` 自己也改用它——
同源，杜绝将来再漂移。两条线的书架都传它。修完：

| 当前手册 | 沙箱根 | 书架 |
| --- | --- | --- |
| `swe-agent-v2`（仓库根） | 仓库根 | **空**——师傅答「我没读到」是实情 ✓ |
| `writeback-fixture`（vault） | vault | 印 vault 里那本，`read_file` ok=True ✓ |
| `vault-swe-agent-v2` | vault | 印 fixture，ok=True ✓ |

另有一路报「插件标准部署（不配 `PEN_ALLOW_ROOTS`、靠请求体 `vault_root` 登记）下
书架恒为空，整个 v0.8.7 是空转」。改用 `reading_roots` 之后不成立——
`register` 会把 `vault_root` 落成 `meta.allow_root`，闸走的就是它。已补端到端测试锁住。

### P1 · 缓存键只有 current_path——要修的症状原样复发

读者刚在 Obsidian 里打开另一本书（登记），**60 秒内书架里看不见它**，
师傅照旧答「我没读到」。而且我自己引入了同一个 bug 的另外两半：
`with_paths` 两种格式、两条线不同的 `allow_roots`，共用一个键就是互相投毒。
键改成 `current_path × with_paths × allow_roots × registered` 全量。

### P2 · `SHELF_CHARS=1500` 是按旧的单行格式估的

`with_paths` 是**两行一组**。8 本长标题 + iCloud 那种深路径会被静默砍掉最后几本——
读者的书架上凭空少两本书，还看不出为什么。按 8 × 2 × 200 给到 3200。

顺带另一路报的：预算把首行也截掉时，**段头还在、条目却是空的**——
等于向模型断言「有别的教材」然后一本都不给，它只能凭空编。改成整段不出现。

### P2 · 「同一棵树」按父目录算，vault 分了子目录就失效

对抗验证 **confirmed**（另一路在隔离 tmp 里原样复现）。手册放在 `vault/level0/` 时，
`base` 是 `vault/level0`，`vault/` 根下的兄弟书是它的**兄弟不是后代**，判定为「远」，
于是退到 mtime 比大小——仓库那份被 `git pull` 刷新过就会赢，绕回原来那个 bug。
改成按**读取根**算。

### P2 · `except OSError` 比它调用的东西窄

`Path.resolve()` 对含 `\x00` 的路径抛 **ValueError**、对 symlink 环抛 **RuntimeError**，
都不是 OSError。逃出 `sorted()` 的 key 就掀掉整张书架，而调用方只看得到一个空串——
症状和「没有别的书」一模一样，没法从现象倒推。本文件六处 `except` 一律放宽。

### 被反驳掉的

- 「`_prefer_nearby` 与 `_shelf_paths` 反查错位」——审的是 HEAD 不是工作树，
  我在审查启动后已经改了。
- 「首行超预算的覆盖洞」——报告自己写明「现状代码是安全的，这是覆盖洞不是活 bug」，
  触发条件是「改源码」而不是输入。
