# v0.7.0 — 中英文切换

> 插件既面向国内也面向海外。界面、后端错误文案、AI 回复语言三层都要跟着走。日期：2026-08-20。

## 三层，分别怎么解决

| 层 | 归属 | 做法 |
| --- | --- | --- |
| 插件界面 | `obsidian/src/i18n/` | `zh.ts` / `en.ts` 双表，`Dict` 类型强制 |
| 芯片按钮、状态行 | 后端下发，但带稳定 id | 前端按 `chip.id` / `ev.phase` 查表，查不到就照抄后端原文 |
| sidecar 错误文案 | `pen/i18n.py` | `Accept-Language` 头选表 |
| AI 回复 | `pen/session.py` | 按语言给 system prompt 追加一句回复语言指令 |

## 前端：类型强制与它挡不住的那个洞

`zh.ts` **不加 `as const`** → `export type Dict = typeof zh`；`en.ts` 写 `export const en: Dict = {…}`。那一行 `: Dict` 就是全部的强制力。实测三种破坏方式：

| 破坏 | 结果 |
| --- | --- |
| 删一个键 | ✅ TS2741 Property is missing |
| 多写一个键 | ✅ TS2353 excess property |
| 带参函数少收一个参数 | ❌ **没报错** |

第三条是 TypeScript 的设计（JS 里忽略多余实参本来就合法），`strictFunctionTypes` 也管不了。但它会造成真实的静默文案 bug——比如 `healthOkFallback` 英文版少收 `model`，英文用户就永远看不到模型名。补了一个模块级自检：比对中英两表里同名函数的 `length`，不一致就 `console.warn`。已验证能抓到。

文案 API 用**函数式**（`t().usage(ctx, out)`）而不是插值式（`t("usage", {ctx, out})`）：插值式要类型安全就得写模板字面量类型解析器从 `"上下文 {ctx}"` 里抽键名，而那要求 `zh` 用 `as const`，一旦 `as const`，`typeof zh` 全是字面量类型，`const en: Dict` 就永远无法满足。对一个千行插件是过度工程。

## 语言探测（已核对 Obsidian 实现）

`getLanguage()` 自 1.8.7 才有，而 `minAppVersion` 是 1.5.0，必须 guard；它的实现就是 `localStorage.getItem("language") || "en"`。

**关键细节：用户选英文时 Obsidian 是 `removeItem`**，所以读到 `null` 要当英文，不能当"没设置过"再去猜系统语言。判定写 `startsWith("zh")`，`zh` 与 `zh-TW` 都吃简体表——比退回英文更接近繁体用户。

不需要监听变化：Obsidian 自己改语言必定走 `window.location.reload()`，一次会话里这个值不会变。

已 smoke test 覆盖：localStorage 为 null、老版本没有 `getLanguage`、用户加载自定义翻译文件时 `language` 存的是一个绝对路径（`startsWith` 天然容忍）。

## 热切换：不需要重启插件

| 表面 | 切换后 |
| --- | --- |
| 侧栏全部文案 | 立即（`relocalize()` → `renderShell()`） |
| Ribbon tooltip | 立即（`setTooltip`） |
| Tab 标题 | 立即（`updateHeader()`，兜底 `setViewState(getViewState())`） |
| 命令面板 | 下次打开面板 |
| 设置页 | 立即（`this.display()`） |

两个坑：

1. **Ribbon 注册标题必须语言无关**。ribbon 项的内部 id 是 `manifest.id + ":" + title`，用户在「外观 → 功能区」里的排序和隐藏状态按这个 id 存。换语言就换标题会让那份配置变成孤儿。所以注册时写死 `"Socrates Pen"`，真正的文案用 `setTooltip` 覆盖。
2. **改命令名要自己把前缀补回来**。`addCommand` 只在注册那一刻做过一次 `manifest.name + ": "`。id 不变，所以用户已绑的快捷键不受影响。（命令名重复前缀那个老 bug 是 v0.5.0 修的，不在本版记账。）

`relocalize()` 里还要重新 `probeHealth()`：`health` 存的是**已成文**的字符串。`usage` 因此改成结构化 `{ctx, out}`，成文推迟到渲染时。`err` 可能是 sidecar 下发的原文，本就不翻，保留不动。

## 后端：走 Accept-Language 头，不加 body 字段

给 `LlmOverrideBody` 加 `lang` 只能覆盖三个 POST；改成 `Accept-Language` + 一个 FastAPI 依赖，一处定义就够，且不用改七个 Pydantic 模型。全站 20 条路由里 17 条声明了这个依赖，其余 3 条（`/v1/health`、`/v1/handbooks`、`/v1/chips`）不产任何文案。

`pen/i18n.py` 收 23 条会显示到插件界面上的文案：`provider_error_message` 四条（用户最常撞到的：钥匙不对 / Thinking 档不支持 / 连不上节点 / 意外错误）、HTTPException detail、SSE `error.message`。`lang` 经由 `stream_chat` / `resume_chat` / `_agent_loop` / `propose_fold_md` 透传。

没有带 `Accept-Language` 时回落中文——`web/` 客户端还没接这个头，不能让它突然变英文。

## 回复语言

`system_prompt(lang)` 在中文人设后**追加**一句语言指令，不整体翻译——人设的语气是这本手册的一部分，翻过去会走味，而模型完全能读中文指令、用英文作答。测试断言 `en.startswith(zh)`，防止以后有人把它改成两份独立 prompt 然后各自漂移。

**只对新会话生效**：`SYSTEM_PROMPT` 在 `PenSession.__post_init__` 就写死进 `messages[0]` 并落盘。`PenSession` 新增 `lang` 字段并持久化，重载 sidecar 后仍在。

## 已知边界

1. `chip_label()` 把中文 label 写进 `ui_messages` 并落盘（`app.py`）。恢复旧会话时，历史用户气泡仍是当时那个语言。新发的都是本地化的。干净解是后端多存一个 chip id，留到下一版。
2. `manifest.json` 的 `name` / `description` 无法本地化（Obsidian 直读 JSON）。description 已改英文——社区插件列表面向全球。
3. **上游模块的异常文案暂未覆盖**：`sandbox.py` / `insert.py` / `libraries.py` / `index.py` / `snapshots.py` 抛的中文异常经 `str(exc)` 变成 400 detail。它们要本地化得改异常设计（带 key 的异常类），是独立一版的工作量。这些都是边缘路径（拒绝越权路径、折叠块 lint 失败），用户日常不会撞到。
