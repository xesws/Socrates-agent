# v0.8.3 — 双层机制的审查修复

> v0.8.0–v0.8.2 落地后的自查与审查修复。日期：2026-08-20。

## 自查发现（七条，全部已复现）

### P0 · 深题关一次侧栏就永久丢失

`docs/v0.8.1` 里写了「`to_public()` 需要时在 app 层包一个 `_public_session()` 拼」，**但这个函数根本没写**。`to_public()` 的 `dyn_chips` 只有 `sess.last_chips`（实时层那两条），深题躺在 `probe_store` 里从没被拼进去。

后果：已经花钱挖出来、也给读者看过的问题，关一次侧栏就没了。而 v0.8.2 的 commit message 里那条对抗剧本「深题从 getSession 回来」，实际上是假的。

复现（`GET /v1/sessions/{id}` 只回来 quick）→ 补 `_public_session()`，把 `state in ("shown","clicked")` 的深题拼在前面。**pending 的不拼**——没成熟的不能因为重开侧栏就提前冒出来，这条也写进了测试。

### P0 · 日配额是个死常量，成本上限根本没生效

`PROBE_MAX_PER_DAY = 40` 定义了，全仓库**零引用**。只有每会话 8 次这一道闸，而「开一堆新会话」就能绕过去——用户选触发频率时看到的「每小时 40 次上限」是不存在的。

复现：连开 6 个新会话各探一次，6 次全部放行。修完后按 `.pen/probes/<hid>/daily.json` 跨会话累计，跨天自动归零。

### P1 · 英文好问题被长度带整批误杀

`MIN_CHARS=8 / MAX_CHARS=60` 是拿 47 条中文历史调出来的。中文一个字就是一个信息单位，英文去掉空格后字符数是它的两三倍。实测：

```
len= 65 ✗挡  Why is mini-swe-agent the first reference implementation and not LangChain?
len=108 ✗挡  How does the approval gate stay a separate piece instead of ...
```

第一条正是 `docs/v0.8.0` 里被我列为「好例」的那条的英文版。插件从 v0.7.0 起就是双语的，这等于英文用户的相关问题功能半残。

改成按字形分带：CJK 占半数以上走 8–60，否则走 20–170。中文那 47 条回归仍是零误伤。

### P2 · `PROBE_MAX_CALLS` 是个说谎的常量

定义了 `= 2`，但 `explore()` 的两段结构是硬编码的，不读它。改这个常量不会有任何效果，而看代码的人会以为改了有用。删掉，上限改由两条断言锁住（「要正文时恰好两次调用」「读取不超过 `PROBE_MAX_READS` 段」）。

### P2 · `_harvest` 的相互近似去重失效

它逐条调 `clean_candidates(limit=1)`，而相互去重是在**一批之内**做的——每次只喂一条，那段逻辑永远不触发。只有精确 key 去重在起作用。「每轮都探」会把近似重复放大，所以补了 0.72 的两两检查，也跟 `asked` 比一遍。

### P1 · `spawn()` 失败会把坑位占死五分钟

`_maybe_probe` 里 `try_claim` 成功之后，组装 job 或起线程如果抛异常（线程耗尽、
`libraries` 读盘失败……），整段被外层 `except Exception` 吞掉直接 return False，
**但坑已经占上了**。孤儿回收要五分钟，期间这个会话一次都探不了；更难看的是正在
轮询的前端会看到 `running` 非空，对着一个永远不会完成的幽灵白等满 90 秒。

复现（monkeypatch `spawn` 抛 `RuntimeError`）：

```
spawn 炸了之后 running = ['a0b48fa678f3']
前端还会对着这个幽灵轮询满 90 秒：running = ['a0b48fa678f3']
```

改成占坑之后单开一个 try，任何异常先 `release` 再返回。

### P2 · 书架缓存无界增长

`library_scan._CACHE` 按 `current_path` 存，sidecar 长期开着、读者打开很多篇笔记
就一直涨。实测打开 120 篇后有 120 条。加了 64 条上限，满了淘汰最旧的。

## 实测记录：相似度阈值在双语下的表现

| 相似度 | 判定 | 场景 |
| ---: | --- | --- |
| 0.79 | 合并 | 英文，只换了对比对象（LangChain → AutoGPT） |
| 0.42 | 保留 | 英文，同一个意思不同措辞——**漏网，但方向保守** |
| 0.15 | 保留 | 英文，两个完全不同的问题 |
| 0.62 | 保留 | 中文包含关系（长句包含短句） |
| 0.04 | 保留 | 中文两个不同问题 |

结论：阈值可用，英文的语义去重比中文弱，但宁可漏也不误杀，符合「防误杀比防漏更重要」的原则。
