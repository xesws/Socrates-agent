# v0.12.12 — 闸的闸也得同源

v0.12.11 给两条槽位扫描加了一条「防瞎」断言：数一下真的扫到了多少文件和
多少个键，掉到 0 就说明闸自己瞎了。方向对，但**那条防瞎断言自己就瞎着**。

## ① 「两个闸不同源」——这回栽在闸的闸上

```js
const wrongInErr = [...src.matchAll(/this\.err\s*\+?=\s*([^;]*);/g)]  // 执法的
...
const seenErr    = [...src.matchAll(/this\.err\s*\+?=\s*([^;]*);/g)]  // 数数的，抄了一遍
```

审查的实测：**只**把执法那条写坏（`this.err` → `this.errr`），数数那条
保持原样 → **57 项全部通过**，防瞎闸一声没吭。

因为 `seenErr` 测的是它**自己那份副本**，不是真正在执法的那一份。
而加这条断言的全部理由就是「防正则写错还报绿」——改的人只会改执法那一行，
那正好是它看不见的那一种。

改成一份：

```js
const ERR_ASSIGN = /this\.err\s*(?:\+|\|\||\?\?)?=\s*([^;]*);/g;
const errStmts   = [...src.matchAll(ERR_ASSIGN)];
const seenErr    = errStmts.flatMap((m) => keysIn(m[1]));
const wrongInErr = seenErr.filter((k) => !k.startsWith("err"));
```

Notice 那边本来就是同源的（`noticeArgs` 只算一次），err 这边是唯一一处两份。

「两个闸不同源」是这个仓库反复栽的坑（v0.8.8 的书架闸、v0.12.6 的 SSE
错误分支）。这一次栽在**闸的闸**上——更难发现，因为它坏掉的表现是「全绿」。

## ② `\+?=` 看不见 `||=` / `??=`

不是假想。`PenView.ts:1066` 现在就是：

```ts
if (!this.err) this.err = t().errSessionArchivedHard;
```

这正是 eslint / prettier / 任何一个「简化一下」的建议会改写成
`this.err ||= …` 的形状。改完那一刻这条闸就再也看不见它了。

`\+?` 换成 `(?:\+|\|\||\?\?)?`。放宽不会误伤：比较形式
（`this.err ==` / `!=`）全仓 **0** 处，查过了。

## ③ 「函数型的由下面那条 arity 自检守」——假的

```js
if (typeof v === "function") continue; // 函数型的由下面那条 arity 自检守
```

`src/i18n/index.ts` 那条 arity 自检的条件是
`typeof a === "function" && typeof b === "function"`——**en 那边一旦不是
函数它就直接跳过、一声不吭**。它只管「两边都是函数、但形参个数不一样」。

审查实测：把 `en.approvalTarget` 从函数改成 `"oops"`（不加 `as` 强转，
就是手滑那种写法）→ `node scripts/check-i18n.mjs` **57 项全部通过**，
只有 `tsc --noEmit` 报 TS2322。

而 **`npm test` 不跑 tsc**（只有 `npm run build` 跑）。只跑 `npm test`
的人会拿到一个全绿的坏英文表。而那句注释会让下一个读它的人以为
这 20 个函数键已经有人守了——**又一次断言了一个自己并不知道的因由**，
这已经是这一串里的第四次。

改成在 `walk()` 里自己查一句。理由：这是 `npm test` 里唯一一条通吃的闸，
不该把自己的覆盖度记在一个不在 `npm test` 里的工具头上。

## ④ 一处过期的键名

`PenView.ts:1061` 的注释还写着「顶上那条早退写 `noticeRegisterFirst`」
——v0.12.10 起写的是 `errSessionGoneNoHandbook`。这条注释念出来的是一个
**新闸会判红**的写法（`notice*` 进 `this.err`），而它所在的块正是解释
那条不变式的地方。

（另两处提到 `noticeRegisterFirst` 的注释查过，都准确：`:909` 说的是
「不复用它」，`:1189` 指的 `:901` 那条早退位置也对。）

## ⑤ 文档里那个字数

## 查过、决定不动的

- **`[^;]*` 在字符串字面量里的 `;` 上切断**：
  `` this.err = `a; ${t().noticeX}` `` 和 `this.err = "a; " + t().noticeX`
  都能全绿逃逸。**是真洞**，但审查把 `src/**/*.ts` 里全部 22 条
  `this.err` 赋值逐条看过，右值里一个半角 `;` 都没有——潜在洞，不是现行洞。
  真要治得剥字符串字面量，代价比现在能挡住的东西大。
- **过度捕获的方向是安全的**：Notice 那条的非贪婪 `[\s\S]*?` 在缺分号时
  会往后多吞一段，结果是**多**看见键（可能误红），不会少看见。
  往误报倒不往漏报倒，这个方向对。
- **别名 `const s = t()` 和方括号 `t()["x"]`** 照旧看不见。没有现成的诱因
  把代码往那儿推（`||=` 有，所以那条修了）。
- **en 独有键** `walk()` 不看，但 tsc 会红 `TS2353`，有人守。
- 顺带一条实测记录：`readdirSync` 的 `recursive` 是 Node v18.17 / v20.1
  才有的。老 Node 上这条闸会**响亮地**挂掉（扫到 9 个文件 / err 0 个 →
  防瞎断言报红），不是静默少扫。
