## 第三条：50 → 100（本节已完成）

`pen/tutor.py:20`。读者要的就是宽：接上书架之后，一个跨教材的问题本来就要多翻

成本那头不是没人管：`CROSS_BOOK_CHARS=24000` 和 `CROSS_BOOK_READS=8` 两道闸仍在，
**读别的书**累计 24000 字符或 8 次就叫停。所以这次放宽的实际上是「翻本册」的余量，
跨书那部分的花费不随轮数上限变化。

顺带把 `pen/probe.py` 和 `pen/config.py` 注释里提到 50 的地方一起改了——
注释里写着旧数字比不写更糟。

## 第一条（D4）：待探查结果补齐

已确认的前提（实测）：

**probe 的读取根永远是实时对话读取根的子集。**

```
probe 的根 = job.extra_roots or [REPO_ROOT]
实时的根   = [REPO_ROOT, *extra_roots]
```

- `extra` 非空：probe = `extra`，实时 = `[REPO_ROOT] + extra` ⊇ probe
- `extra` 为空：两边都是 `[REPO_ROOT]`

四本真实登记手册逐个验证，`probe ⊆ 实时` 全部成立。

**意义**：后台探索能读到的书，读者点开那条题之后，师傅在实时对话里**一定读得到**。
所以跨书出处不会出现「标了出处但点开读不到」的断链——这是 D4 能成立的前提。
（反过来不成立：实时能读到的，probe 不一定能读到。那不影响本方案。）

## 第一条（D4）：五路探查的结论

### 先更正我自己的病症描述

我跟读者说的是「另一本书的行号一律判为不存在 → 拿不到出处 → 被标成凭记忆讲」。
**这只对了一半**，两路探查独立指出了另一半，实测复现：

```
当前手册 13083 行
锚点 L60   _anchor_ok=True → 被算成当前手册的「开篇 / 全景图：七块积木」
锚点 L500  _anchor_ok=True → 被算成当前手册的「Level 0 / 第四拍 · 设计」
锚点 L3000 _anchor_ok=True → 被算成当前手册的「Level 2 / 第一拍」
填了另一本书的 level（"Level 3"）→ _anchor_ok=False
```

`_anchor_ok` 的最后一行是 `return not claimed or claimed == sec.level`——**level 可以不填**。
于是：

| 模型的行为 | 结果 |
| --- | --- |
| 老实填了另一本书的 level | 被拒 → 退到 `open` → 读者点开听到「我凭记忆讲」 |
| 省事没填 level | **通过，但出处是假的**——题在讲另一本书，锚点指向当前手册的无关行 |

第二种更糟，而且它**今天就在发生**。所以给 anchors 加 `book` 在诚实账本上是**收紧**，不是放宽。

### 还有一条自相矛盾的 prompt

一条跨书 `open` 题被点开时，同一个 packet 里：

- `[工作目录里的其他教材]` 段：递给师傅一条**真实路径**，并说「先用 read_file 按 path 读，读了再说」
- `[意图]` 段（`open_intent`）：命令它「这题手册里没有出处，凭你自己的知识讲……不要编文件路径」

**现状不是贴了句假免责声明，是把师傅从当时唯一通畅的那条路上主动劝退了**——
沙箱放行、本轮跨书预算满额（24000 字符 / 8 次），它本可以直接去读。

## 定下来的设计

### 1 · 不加 grounding 第三态

`grounding` 是有校验分支的枚举，加 `"shelf"` 不会以任何方式报错——它会静默落进 `book`
分支，这恰恰是危险的地方。而 `anchors[].book` 是天然的全函数：每条锚点自己说明出自哪本。
存储侧零迁移（`anchors` 是无 schema 的 `list[dict[str, Any]]`，asdict 进原样出，
拿磁盘上的真数据两个方向都跑通了）。

**但顶层字段绝不能随便加**：`DeepQuestion.from_dict` 的 `except TypeError: continue`
会把整池**静默清空**（实测 2 条 → 0 条，不报错）。

### 2 · anchors 一次性解析，五条轴吃同一份

解析成 `(哪本书, 那本的 HandbookIndex, Section)`，然后：

| 轴 | 跨书下怎么判 |
| --- | --- |
| `bridge` | 按 **(book, level)** 去重，不按 level 字符串——两本书都有「Level 0」 |
| `vs_real` | 第三拍在 **anchor 自己那本**里查；另一本没有八拍体例 → 必须有一条**本册**第三拍锚 |
| `altitude` / `tradeoff` / `failure` | 只依赖 `_anchor_ok`，跨书打开后会变成**免检通道**（随便指另一本任意一行都能过）→ 加一条通用判据：**至少一条锚落在本册** |

第三方教材经 `_classify_h1` 全归「封面」、一条「第三拍」都没有，所以上面两条不是理论担心。

### 3 · 书名→路径的解析必须共享

现在这套逻辑内嵌在 `_read_excerpts` 里。anchors 校验需要同一份——
**再抄一遍就是本仓踩过三次的同一个坑**（书架的闸 vs read_file 的闸、两处各拼一遍根、
两处各筛一遍书）。抽出来。

### 4 · `anchor_source` 跟着 book 走

它现在对每条 anchor 都读 `original_path`，带 book 之后会拿**错文件**当出处语料，
反引号校验就成了摆设。

### 5 · 病根在书架：它一个行号都不给

模型只能猜 60/500/3000。给书架每本补上行数（`+10 tok/本`，书架在 user message 里、
对前缀缓存零影响）。

**别本的目录不进 system**：实测 +1919 tok/本（system 涨 31%，八本满员 3.5 倍），
而模型在别本里最多只能真读到 2×80=160 行——多出来的目录只会诱导它写没读过的行号。

### 6 · 点击时按 anchors 分派 intent

`app.py` 的 `intent_extra` 现在是个**布尔分支**（open 就注入「凭记忆讲」）。
跨书题要走另一条：告诉师傅**那本书的路径**，让它去读。
已实测的前提：`probe` 的读取根**永远是**实时对话读取根的子集，所以点开那一刻
师傅一定读得到，而且有满额预算。

### 7 · 顺手要修的三处（不修就会咬人）

- **`_ripe` 的 later 投递会认错书**：他书 Level 1 的题，会在读者走到**当前书** Level 1 时弹出（已跑通复现）。
- **跨书取索引抛异常会被 `run_probe` 的裸 except 吞掉**，整轮探索全废且不退配额 → 必须就地吃掉。
- **`libraries.save_index` 是非原子 `write_text` 且全无锁**：两条 probe 线程同时撞一本刚过期的书，
  实测 **5% 概率** JSONDecodeError。`session.py` 和 `probe_store.py` 早就有 `_atomic_write` 可抄。

### 8 · 三处 prompt 措辞会变成假话，必须同批改

- 「行号说死」段把世界切成「当前手册 / 手册以外的记忆」两格，别本书无处可归——**这是 open 的直接来源**。
- 「材料不够时」段那句「不确定就别写」，正好把跨书锚**唯一的合法来源**（need_read）劝退了。
- schema 的 anchors 加 `book`，照 `need_read` 已有的句式写，再补一句带后果的反向禁令
  （当前手册的锚别填 book）。
- `PROBE_ENGLISH` 那句 "Keep every key name … exactly as specified above" 加字段后仍成立，
  但要补一句**书名不许翻译**。

### 9 · 侧栏不标「出自另一本书」

和读者当初「external-knowledge 类问题不做任何标注」那条决定一致，不冲突。
`to_chip()` 确实不外露 anchors（两个出口都走它，核实过）。

## 验证

- 跨书锚点用**那本书**的索引验证；老实填 level 的不再被拒。
- **今天那条假阳性被堵死**：不填 level 的跨书锚不再被静默算成本册。
- 五条轴各一条跨书用例；`altitude/tradeoff/failure` 的免检通道被「至少一条锚落在本册」堵住。
- `anchor_source` 取的是 anchor 自己那本的正文。
- 点开跨书题时 packet 里给的是「去读那本书」，不是「凭记忆讲」。
- `_ripe` 不再把他书 Level 1 的题投递到本书 Level 1。
- 既有 13 条 `validate_slots` 断言原样成立；`pytest`、突变表全绿。

## 实现：读者一句话砍掉了大半

我原本在写「加载另一本书的索引、用索引验证行号」。读者打断：

> 你如果想让 question-deep-dive 去用另一本书的行号当出处，直接给他权限，
> 让他直接可以 read_file 不就行了？read_file 就会 return 带行号的情况，对吧？

**他是对的。** 深挖这条线本来就在用 Python 代执行 `read_file`（模型不给 tools），
读回来的正文每行都带真行号：

```
〔出自《手搓 SWE Agent 通关手册 v2 · …》〕
205	三层别搅在一块——终端是窗户，shell 是窗户里的人，Bash 是其中一个具体的人：
206
207	```mermaid
```

**行号是我们自己读给它的。** 那就没有「这行存不存在」需要验证——
要验的只有一件事：**这行是不是我们本轮真读过的那几段之一**。
模型读了 L205-211 却在 anchor 里写 L3000，那才是编。

这一句话绕开的不只是代码。探查在「加载别本索引」那条路上挖出一整串坑：

| 坑 | 实测 |
| --- | --- |
| `libraries` 全无锁、`save_index` 是裸 `write_text` | 两条 probe 线程同撞一本刚过期的书，**5% 概率** JSONDecodeError |
| 索引损坏但原文 mtime 没变 | **永久中毒**，`load_index` 每次都抛，永远不自愈 |
| 保 mtime 的复制（`cp -p`、rsync -t、iCloud 回灌） | 索引不重建，`locate()` 一脸自信地给出错的关号 |
| 跨书取索引的异常 | 会被 `run_probe` 的裸 except 吞掉，**整轮探索全废且不退配额** |
| 路径 → handbook_id | **不是单射**，真实登记表上同一份 vault 手册就登记了两次 |

**这些坑现在一条都不用管**——简单路线根本不加载别本索引。

## 改了什么

| | |
| --- | --- |
| `resolve_book()` | 书名→路径的解析从 `_read_excerpts` 里抽出来，`need_read` 和 `anchors` 共用。再抄一遍就是本仓踩过三次的同一个坑 |
| `Anchored` | 一条 anchor 解析完的样子（哪本书、哪一节、哪几行）。五条轴吃同一份，别各自去碰 idx |
| `resolve_anchor()` | 本册用索引验；**别本只验「是不是我们真读过的那几段」** |
| `_read_excerpts()` | 顺带交出真读过的区间。记的是**实际读到的范围**（受 `PROBE_READ_LINES` 封顶），不是模型要的范围——不然它写 `end=99999` 就等于拿到整本书的通行证 |
| `bridge` | 按 **(书, 关)** 去重。两本书都有「Level 0」，按字符串去重会把跨书搭桥直接毙掉 |
| `vs_real` | 第三拍是本手册特有的八拍体例，跨书锚恒不满足 → 必须有一条本册第三拍锚。这正是它该有的样子 |
| **新增通用判据** | **至少一条锚落在当前这本**。少了它，`altitude`/`tradeoff`/`failure` 在跨书下就是免检通道 |
| `anchor_source` | 跳过带 `book` 的锚——那几行的正文在 excerpt 里，别拿错书当出处 |
| 反引号语料 | **只有真指了别本时才把别本正文放进袋子**。不填 `book` 的锚是本册锚，它引用的词就该在本册那几行里 |
| 书架 | 补上**行数**。模型要拿行号点读，不给行数它只能瞎猜 60/500/3000——这才是病根。一本 +10 token |
| `cross_intent()` | 读者点开跨书题时告诉师傅「先 read_file 把那几行读出来再开口」，不再走 open 那条「凭记忆讲」 |
| `_ripe` | later 投递要求本册也有一条锚落在那一关，否则别本 Level 1 的题会在读者走到**本册** Level 1 时弹出 |
| prompt | 三处措辞（「行号说死」「材料不够时」「anchors schema」）+ 英文版「书名是标识符，不许翻译」 |

## 功能通了，但模型不主动用——记下这个事实

半模拟端到端验证通过（喂一个 `need_read`，第二轮产出合法跨书锚、`grounding=book`、
点开给师傅的是「去读那几行」）。**但真跑三次，模型三次都回 `need_read: []`。**

第一次：只有书架，没有额外引导。
第二次：`bridge` 轴补了「桥的另一头可以是别本，最值钱的一种桥，但必须真读过」。
第三次：加了**确定性提示**——读者的话里真出现书架上某本书的名字（中文 ≥4 字才算，
避免「教材」「Agent」这种误报），就在 user message 里直接摆出来：
「读者已经在拿它跟手上这本比了。要拿它出题就先 need_read 去读那几行。」
实测提示确实进了 prompt，模型看到了，仍然不读。

它三次出的题：

> 「你在试验田只练到 Level 1，那本正课却要到 Level 6，中间的手感去哪补？」
> 「这两本手册的关系，也能用『一类和实现』来套吗？」
> 「练出来的手感搬到正课那台机器上还作数吗？」

**这三题都不需要读另一本书的正文**——问的是两本书的**关系**，锚在本册封面就够，
而且题本身不差。模型的判断很可能是对的。

**所以停止加码。** 继续逼它读只会换来一道硬凑的跨书题，读了 80 行正文还不如现在这几题，
而读者当初提这个需求时的原话就是「不能采用无限制的广度搜索，成本太高」。
现在的状态是：**路通了、引导在、真需要时能走**，但不强迫。

这条留给真实使用去检验——读者的 vault 里现在只有真手册和一个测试夹具（`writeback-fixture`，
内容是「shell 是一类、Bash 是实现」的单点小卷子），两本内容关联本来就弱。
等 vault 里出现内容真正相关的第二本教材时，这条路的价值才会显出来。

## 换一个「必须读正文才答得出」的场景——模型读了

前三次不读，第四次把场景换成读者直接点名问另一本书的**具体讲法**
（「那本《通关手册》Level 0 讲 Bash 用的比喻跟这本一样吗？我记得它说过窗户什么的」，
师傅答「我手上这本只写了一句…那本用了什么比喻，我得翻开看才知道，不能替它说话」）：

```
▸ 模型要读: 《手搓 SWE Agent 通关手册 v2…》 L1-500
▸ 真读到 3643 字符，区间 (1, 81)        ← 被 PROBE_READ_LINES=80 截住
```

然后第二轮产出了一条**模型自己写的跨书 bridge 题**：

> 这一本把 shell 讲成『一类程序』，那本把 Bash 讲成『Agent 的手』
> ——真到你敲命令那一步，哪边的说法管用？
> 锚 本册 L7-12 + 锚《手搓 SWE Agent 通关手册 v2》L16

**所以三次不读不是引导不够，是那三个场景本来就不需要读。** 需要的时候它会读。

### 但这一条当场被我自己的校验毙了

`grounding=book`、两个锚都对，最终却 `产出 0 条 no-candidate`。原因是模型把本册那个锚的
level 写成了 `"封面 / 概念对比：一类 vs 实现"`——它抄的是 prompt 里
`位置：{level} / {beat} / {q_title}` 那个格式，而合法 level 只是第一段。

**一条完全正确的题，因为格式多写了几个字被整条毙掉，351 秒的探索白走。**
level 的作用是交叉验证行号，不是考格式。改成只比第一段；真写错关号（`Level 9`）仍然拒。
把真跑那条题原样回放，现在留下来了。

### 真跑还暴露的两个数

- **总耗时 351 秒 > 前端轮询预算 300 秒。** 题不会丢（进池子，下一轮对话搭便车下发），
  但读者**当轮看不到**，「实时抛出」那半条设计就白搭了。
  轮询是本地 HTTP、`busy` 早已 false，界面不受影响；白跑一次真金白银的 LLM 调用
  却看不见才是真浪费。预算 300 → 480 秒（`running` 一空就停，正常跑不满）。
- **351 秒对不上 `PROBE_TIMEOUT=90`。** OpenAI SDK 默认 `max_retries=2`——
  超时不是失败，是**再花一次输入 token 重来**，而且读者看不见。
  `90×3 + 退避` 正好落在 351 秒这个区间。跨书那轮 prompt 要多背 3600 字符正文，
  90 秒本来就偏紧。调到 150 秒。

`pytest 304 passed` · 突变表 19 项全红 · `pen.index --check OK` · `npm run build` 4 项全绿。
