# v0.10.1 — 参数透传骨架

> 纯结构改造，**零可见变化**。验收标准就是这一句：
> `pen/tests/test_*.py` 一个字符不改，全绿。
> 日期：2026-08-20。

## 为什么要有这么一版

读者要「设置页能配翻书轮数、深挖参数」。但今天所有这些数字都是 Python 的
模块级常量，而且有四处是**导入期冻结**的——改了不生效。

更要命的是结构：**sidecar 是多会话共享进程**，设置页在 Obsidian 端。
所以参数只能像 `model` / `thinking` 那样**每请求透传**：

- 写全局可变槽 → A 库的设置串到 B 库的会话上；
- 而且改设置的那一刻正在跑的会话会中途换闸。

**而后台深挖跑在守护线程里，请求早就结束了。** `ProbeJob` 今天只冻结了 `cfg`，
一个限流值都没冻。这是整个改造最大的结构性障碍。

这一版只搭管道，一个语义都不新增。**把语义混进来，「所有现有测试不改一个
字符」这条验收标准就作废了，而它是整个 v0.10.x 唯一的安全网。**

## 一个类，不拆两个

`config.RuntimeLimits`，主对话线和 probe 线共用，靠 `probe_*` 前缀分区。

拆两个的唯一收益是「probe 线程手里少几个它不读的 int」；代价是两张 clamp 表、
两个 merge、两个请求体字段、两组词表键。而本仓「两个闸不同源」踩过三次
（v0.8.8 书架闸 vs read 闸、v0.8.9.3 两处各筛一遍书、v0.8.9.4 两处 key 不规范化），
每次都是**同一份语义分裂在两个地方**。

放 `pen/config.py` 紧挨 `LLMConfig` / `merge_llm`：那对组合就是本仓已有的、
唯一的「每请求透传的冻结配置」范式，`RuntimeLimits` + `merge_limits` 逐字对应它。

两条刻意的设计：

- **`RuntimeLimits` 没有字段默认值**，只能经 `default_limits()` 构造。
  于是每个数字在全仓只出现一次（模块常量），`default_limits()` 是唯一的映射表。
- **`default_limits()` 每次调用现读模块属性，不做模块级单例。**
  `test_probe_store.py` 里 `monkeypatch.setattr(config, "PROBE_MAX_PER_WINDOW", 3)`
  能生效，正是因为消费方走属性访问。做成 `DEFAULT_LIMITS = RuntimeLimits(...)`
  就是在修 `probe.py` 那个信号量的同时，新开一个一模一样的坑。

## 只装已经有人读的旋钮

本版 11 个字段，**每一个都有活的消费方**。`probe_keep_per_run` /
`probe_every_n_rounds` 这些要等 v0.10.4 / v0.10.5 它们的消费方落地时再加。

这不是洁癖，是本仓自己写下的禁令（`config.py` 里那段「摆一个 PROBE_MAX_CALLS
在这里而代码不读它，改的人会以为改了有用」）。本版把它从注释升级成一条
机械测试 `test_every_limit_is_actually_read_somewhere`。

## 四处导入期冻结怎么拆

| 位置 | 改法 |
| --- | --- |
| `probe.py` 的 `_SEM = BoundedSemaphore(...)` | `Lock` + int 计数器。**不能**「限额变了就重建信号量」——在飞的线程 `finally` 里 release 的是旧对象，计数永久漂。抢不到时的行为一字不变（退配额、不排队）。 |
| `tools_impl.py` 的 from-import | 加**唯一的 ctx 取值口** `limits_of(ctx)`，取不到时**回落 config 现值，绝不回落 0**——三条手工拼 ctx 的现存测试会从「第 9 次停」静默变成「第 1 次停」。 |
| `tutor.py` 的 `MAX_TOOL_ROUNDS` | 搬进 config.py，**不留别名**（留 `MAX_TOOL_ROUNDS = config.MAX_TOOL_ROUNDS` 就是第二个定义点）。读取走 ctx 不走新参数：`_agent_loop` 两个调用方都已经通过 `_tool_ctx` 拿到 ctx。 |
| `ProbeJob` 没冻结限流值 | 加 `limits` 字段，在 done 那一刻当场冻进来，理由和 `cfg` 一样。用 `default_factory` 而不是必填——必填要改 16 处测试构造点，那就没法说「一个字符不改」。 |

规矩：**纯叶子函数允许 `limits=None` 默认**（保测试、保 monkeypatch）；
**载体和入口不允许靠默认活着**——那才是漏接线会静默的地方，用测试和变异体钉死。

## 请求体：嵌套 dict，不平铺、不用子模型

`LlmOverrideBody.limits: dict[str, Any] | None`。

- 平铺会让 `ChatBody` 变成二十来个字段；
- 用 `dict` 而不是 `BaseModel` 是为了**永远不会 422**——设置页填错一个字符，
  读者该看到夹紧之后的正常回复，不是一个红色 422。

`merge_limits` 只夹紧不报错，看不懂的一律**当没给**而不是当 0（当 0 比报错更难查）。
三个必须挡的输入：`bool`（`isinstance(True, int)` 为真，一个 JSON `true` 会静默
变成上限 1）、`NaN`、`inf`。

## 怎么证明「默认 = 现状」

1. **字面量表测试**：写死 `(100, 24000, 8, …)`，**故意不写 `== config.MAX_TOOL_ROUNDS`**
   ——自指断言什么都证明不了。改任何一个数都要在这里改一次，改的人会看见自己在改行为。
2. 全套现存测试一字不改全绿。
3. **透传是活的**（否则 1、2 全绿而功能是空的）：chat / approve / probe job 各一条，
   且断言「没填的那些必须还是默认」。
4. **ctx 真把闸带到工具里**：手工拼 `ctx["limits"]`，断言第 2 次就撞额度。
5. 变异表：改两条锚点 + 新增三条。

## 不做

- 不加任何还没有消费方的字段。
- 不动前端一个字符。
- 不修 `resume_chat` 的跨书预算泄漏（v0.10.3 单独一版，那是行为改变）。
