# v0.4.3 — 侧栏布局止血

> 纯 CSS，零 TS 改动。审批面板一出现，对话区就被压到 50px——先把地基堵上。日期：2026-08-20。

## 病因

只有一条：**`.sp-bar` 是不滚动的固定头，却没有封顶。**

它从 v0.2.9 起连着装进：健康行 / 错误 / 状态 / 用量 / 选区摘录 / 4 个按钮 / 5 个芯片 + 至多 4 个动态芯片 / 输入框 / 审批面板（含 1600 字符 `<pre>`）。`.sp-log` 是 `flex: 1`（basis 0），只能吃 bar 剩下的，于是被挤到几乎不可见。

`.socrates-pen` 就是 `contentEl`（`.view-content`），主题给它的 `padding` 和 `overflow-y` 一直在参与布局，是个隐藏变量。

### 一条曾经写错的判断

原以为病根是 `.sp-log` 缺 `min-height: 0`（flex item 的 automatic minimum size 是基于内容的，会让 overflow 不触发）。**实测推翻**：

| 实验 | bar | log |
| --- | ---: | ---: |
| 改前原样 | 626 | 50 |
| 只加 `.sp-log{min-height:0}` | 626 | 50 |
| 只加 `.sp-bar` 封顶+自滚 | **423** | **253** |
| 把 `.sp-log` 改成 `overflow:visible` | 626 | 718（撑破） |

规范里 automatic minimum size 有例外：**`overflow` 非 `visible` 时直接解析为 0**。`.sp-log` 本来就有 `overflow: auto`，那行 `min-height` 早就等于 0 了。仍然写死 0，纯防御——将来谁把 overflow 改回 visible，炸法是静默的，只表现为输入框被顶出屏幕。

## 改动

- `.sp-bar`：`flex-shrink: 0` + `max-height: 60%` + `overflow-y: auto` + `overscroll-behavior: contain`
- `.socrates-pen`：`min-height: 0` + `overflow: hidden` + `padding: 0`，显式接管主题默认值
- `.sp-log`：补 `min-height: 0`（防御）

## 封顶不会卡住正常使用

`max-height: 60%` 只在窄栏兜底。实测（审批面板 + 4 动态芯片）：

| 侧栏 | 封顶触发 | 对话区 |
| --- | --- | ---: |
| 300×700 | 是 | 253px (36%) |
| 380×900 | 否 | 334px (37%) |
| 450×1000 | 否 | 520px (52%) |
| 600×1100 | 否 | 648px (59%) |
| 800×1200 | 否 | 777px (65%) |

380 往上封顶就再不触发，bar 按内容自然高度走。

## 不做什么

不动 DOM，不动 TS。输入框仍在顶部、流式期间仍会被重建导致丢焦点、芯片仍会换行成多行——留给 v0.5.0 的骨架重构。这一层只保证 **任何状态下对话区不归零**，且后续任何一步回滚它都还在。
