# v0.8.8 — 书架的闸与 read_file 的闸真正同源

> v0.8.7 修了「书架列得出、师傅读不到」，四路审查坐实。但修完之后是反向的偏差：
> **师傅读得到的书，书架没列出来**。同一条裂缝的另一边。日期：2026-08-20。

## v0.8.7 修了一半

v0.8.7 引入 `sandbox.reading_roots(original_path, extra_roots)`，复刻的是
`assert_readable` 的语义：`extra_roots is not None` 就用它，否则用手册所在目录。

问题在于**调用方传进来的 `extra_roots` 已经不是 `stream_chat` 最终用的那份**。
`pen/tutor.py:283`：

```python
extra_roots = [REPO_ROOT, *(extra_roots or [])]
ctx = _tool_ctx(session, original_path, extra_roots)
```

实时对话里 `read_file` 的真实根是 **REPO_ROOT ∪ 本手册 allow_root**，
而 `app.py` 算书架时传的是 `libraries.extra_roots_for(hid)`——**不含 REPO_ROOT**。

实测（当前手册在 vault、仓库根另有一本别的教材）：

```
我算的书架闸  : ['…/vault']
tutor 实际的闸: ['/Users/tangyiq/dev/Socrates-agent', '…/vault']
按我的闸，书架: ''
按实际的闸    : '- 《Git 默认动作》  path: /Users/tangyiq/dev/Socrates-agent/AGENTS.md'
师傅实际 read_file → ok=True
→ 漏了：读得到却没列出来
```

方向是保守的（不会再印出读不到的路径），所以不是 P1；但「列得出 == 读得到」
这个等式仍然不成立，只是从一边偏到了另一边。而**只要两处各自算一遍根，
就一定会再漂移**——v0.8.7 的 bug 本身就是这么来的。

## 为什么不能简单地在 app.py 里补一个 REPO_ROOT

因为 probe 那条线的语义**不一样**。`pen/probe.py` 的 `anchor_source` 和
`_read_excerpts` 用的是：

```python
extra_roots=job.extra_roots or [config.REPO_ROOT]
```

`or` 不是 `[REPO_ROOT, *…]`：extra 非空时**不含** REPO_ROOT。所以

| 线 | extra 为空 | extra = [vault] |
| --- | --- | --- |
| 实时（tutor） | `[REPO_ROOT]` | `[REPO_ROOT, vault]` |
| 深挖（probe） | `[REPO_ROOT]` | `[vault]` |

两条线本来就该有两个答案。v0.8.7 的 `probe._reading_roots(job)` 已经精确复刻了
probe 那一支，错的只有实时那一支。

## 改法：让根的定义只有一处

`pen/tutor.py` 暴露 `read_roots(extra_roots)`，`stream_chat` 自己也调它：

```python
def read_roots(extra_roots: list[Path] | None) -> list[Path]:
    """stream_chat 给 read_file 的根。**书架的可见性必须调这个函数**，
    不能自己再拼一遍——v0.8.7 那个 bug 就是两处各算一遍漂移出来的。"""
    return [REPO_ROOT, *(extra_roots or [])]
```

`app.py` 改成 `reading_roots(path, tutor.read_roots(libraries.extra_roots_for(hid)))`。

这样「书架列得出」严格等于「read_file 读得到」，而且等式由**同一个函数**保证，
不是由两处注释里的约定保证。

## 验证

- 单测：对同一组 (手册, extra_roots)，`shelf_digest` 列出的每条 path 都能被
  `read_file_report` 以 `stream_chat` 的真实根读到——**正反两向都断言**
  （列出的必可读、可读的必列出），这才是等式。
- probe 那一支的语义不能被改掉：`extra=[vault]` 时 probe 的根仍是 `[vault]`，
  不含 REPO_ROOT。加断言锁住两条线的差异。
- 既有闸门：`pytest`、`npm run build`、`pen.index --check`。

## 附：v0.8.7 审查的一条未决

四路审查里 `review:requirement`（需求覆盖：跨教材这条需求是否真的被满足、
probe 那条线有没有同性质的洞）**因 API 报错中途挂掉，没有结论**。
本版补跑这一维度。

## 实施与验证

`pen/tutor.py` 新增 `read_roots()`，`stream_chat` 自己第一个调它；
`pen/app.py` 的书架调用点改成 `reading_roots(path, read_roots(extra_roots_for(hid)))`。
根的定义现在只有一处。

**双向等式测试**（`test_shelf_visibility_equals_read_file_reachability_both_ways`）：
三本书分别放在仓库根、vault、第三个目录，对每一本断言
`read_file_report(...)["ok"] == (path in 书架)`。任一方向不成立就红。

**probe 那支的语义单独锁住**：`extra=[vault]` 时 `probe._reading_roots` 必须是
`[vault]`（**不含** REPO_ROOT），而 `tutor.read_roots` 是 `[REPO_ROOT, vault]`。
两条线本来就该有两个答案，这条断言防的是将来有人为了「统一」把 probe 那支改坏。

**反证**：把两处改回旧写法，这两条测试立刻红（`2 failed`）——不是空断言。

`pytest 285 passed`（v0.8.7 是 283）· `pen.index --check OK` · `npm run build` 4 项全绿。
