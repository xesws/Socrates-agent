# v0.5.1 — 流式瘦身与滚动保持

> 一条 2400 字的回复会触发 50 次全量重绘；往上翻历史会被一路拽回底部。日期：2026-08-20。

## 流式期间不再全量重绘

后端 `pen/tutor.py` 是 `visible[i : i + 48]`——**每 48 字符一个 token 事件**，不是每字符。一条 2400 字的回复 = 50 次 `paintBar()`，每次销毁重建输入框 + 三个图标按钮 + 至多 9 个芯片。

`token` 与 `status` 分支现在只调 `setStatus()`，它只做一次 `classList.toggle` 和一次 `textContent` 赋值（还带 `!==` 短路）。每个 token 的 DOM 工作量从约 15 个元素降到 1 个文本节点。

配合 v0.5.0 的骨架，这条路径上已经没有任何节点会被重建——输入框里打到一半的字、面板里 diff 的滚动位置都不再丢。

## 滚动位置保持

```ts
private atBottom(el: HTMLElement): boolean {
  return el.scrollHeight - el.scrollTop - el.clientHeight <= 24;
}
```

两处无条件拉底都改成条件式，其中 `paintStreamBubble()` 才是真凶——它每 48 字符拽一次。

**判定必须在 `log.empty()` 之前做**，之后那三个数字已经没有意义。`paintGen` 竞争会让重画循环多跑几轮，`stick` 只在循环外取一次。

实测边界（真实滚动容器）：往上翻 → 不拽回；差 20px（容差内）→ 贴底；**内容未溢出 → 算贴底**（否则首次绘制和空态之后的第一条消息不会滚到位）。

`paintLog(mode)` 加显式参数，不猜：

| 调用点 | mode | 理由 |
| --- | --- | --- |
| 用户刚发出一句 | `force` | 自己说的话必须看见 |
| 换笔记 / 换会话 | `force` | 新一场，不沿用上一场的滚动位置 |
| 允许编辑 / 回退 / 重做 之后 | `force` | 用户主动操作的结果必须可见 |
| 流式结束、工具行追加 | `auto` | 用户在翻历史就别打扰 |
