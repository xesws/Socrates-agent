# v0.12.10 — 不变式做对了，填进去的值挑错了

v0.12.9 把 `reviveSession()` 的早退改成写一句 `this.err` 再返回，
让「返回 `false` ⇒ `this.err` 非空」成了函数自己的不变式。这一步是对的。

但填进去的值我图省事，复用了现成的 `noticeRegisterFirst`
（「先框选并登记当前笔记」）。复审把不变式**可达时读者实际看到的字**
拼了出来，两条路都不对。

## A 路 · `send()`

```
先框选并登记当前笔记
```

**「这场对话没了」整句缺席。** 读者刚发出一句话，界面回他一句
「先框选并登记当前笔记」——他不知道自己那场对话怎么了，只知道被要求
去做个动作。这正是 v0.12.8 特意补回来的那一半，又被「让位」换掉了。

## B 路 · `doApprove()` 的 `+=`

```
zh: 先框选并登记当前笔记（这次写回没有执行，你的笔记没有被改动。）
en: Pick a passage first so this note gets registered (The write-back never ran — your note was not modified.)
```

`errApprovalUntouched` 是**为「前面已经收句」设计的追加物**——zh 以 `（`
开头、en 以 ` (` 开头。挂在一句没有句末标点的祈使短句后面：中文那个括号
像在修饰「登记笔记」这个动作，**英文整句从头到尾不终止**。

而且读者刚点完「同意写回」，界面第一句话是「先框选并登记当前笔记」，
语域完全不对。

## C · 键名和去处对不上

`notice*` 是给 `new Notice()` 写的短祈使句；`this.err` 由 `paintAlert()`
渲染成错误条，进那儿的清一色是 `err*` 前缀的完整句
（`errUnreachable` / `errNoSelection` / `errSessionArchivedHard` / …）。

而 **v0.12.6 ⑤ 立的规矩原话**就是：

> 键名也从 `errSessionArchived` 改成 `noticeSessionArchived`——
> **名字和去处对上，下次不会有人再顺手塞回 `err`。**

那条规矩立起来才三版，第一个破例出现在一行注释写着「别删」的代码上。

## 改法：一条为这个位置写的完整句

```ts
errSessionGoneNoHandbook:
  "这场对话在 sidecar 上已经找不到了，而面板上还没有登记过笔记，没法给你开新的一场。请先框选一次。",
```

四件事一次满足：说了**发生了什么**（A 路缺的那一半回来了）、说了
**该做什么**（可操作性一点没丢）、以「。」收句（B 路 `+=` 拼出来是
「……请先框选一次。（这次写回没有执行，你的笔记没有被改动。）」，顺）、
名字和去处对上。

`:866` 那处 `new Notice(t().noticeRegisterFirst)` 原样不动——在那里它是对的。

## 两条通吃的闸（`check-i18n.mjs` 53 → 56）

这一版真正的收成不是换了个字符串，是**把两条一直靠人记的约定做成了扫描**。

**① `zh` 的每个字符串键在 `en` 里都非空**（当前 111 个键）。
新不变式的前提就是「那个键两张表里都非空」，而 `en.ts` 上的 `Dict` 类型
只挡得住**漏键**，挡不住**空串**。原来那些 check 全是按名字点到的
spot check，一个新键加进来不会被任何东西看一眼。

**② 键名必须和去处对得上**：扫 `PenView.ts` 源码，`this.err =` / `+=`
右边只许出现 `err*`，`new Notice()` 里只许出现 `notice*`。
v0.12.9 自己破过一次这条规矩，所以它不该继续只是一句约定。

三条新闸都做了突变验证，**都会红**（不是空转）：

| 突变 | 结果 |
| --- | --- |
| 把 `errSessionGoneNoHandbook` 的 en 改成空串 | ✓ 会红 1/56 |
| 把 `noticeRegisterFirst` 塞进 `this.err` | ✓ 会红 1/56 |
| 把 `errSessionGoneNoHandbook` 塞进 `new Notice()` | ✓ 会红 1/56 |
