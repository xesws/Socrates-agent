# v0.4.4 — 删掉不可达的写回提案 UI

> v0.4.0 把写回改成 chat + `edit_file` + 人批之后，老的 propose/retarget/apply 那一整套就再也走不到了。纯删除。日期：2026-08-20。

## 为什么它死了

`doPropose()` 零调用点——v0.4.0 的 `2ee9b60` 删掉了 `send()` 里的：

```ts
-    if (chip === "writeback") {
-      await this.doPropose();
```

`this.proposal` 另一个赋值点是 `doRetarget()`，而它开头就是 `if (!this.proposal || this.busy) return;`，无法自举。所以 `this.proposal` 恒为 `null`，`paintBar()` 里那个 `if (this.proposal)` 分支和它调用的 `paintTargetControls()`（120 行、7 项 select）永远不渲染。

`tsconfig` 没开 `noUnusedLocals`，`tsc --noEmit` 不报，所以它一直静静躺在那儿。

留着有真实风险：`send()` 只挡了「有 pending 时不能再 chat」，**没挡反向**——芯片的 `blocked` 只看 `busy || pending`，不看 proposal。万一哪天重新接上 `doPropose`，一发消息就可能同时挂出两个面板。

## 删了什么

- `PenView.ts`：`whereSentence()`、`paintBar()` 的 proposal 分支、`paintTargetControls()`、`caretLine()`、`onTargetKind()`、`doRetarget()`、`doPropose()`、`doApply()`、`noteRelPath()`，以及 `proposal`/`outline`/`targetKind`/`lineInput`/`headingStart`/`qStart`/`rangeA`/`rangeB`/`replaceAck` 九个字段。1025 → 711 行。
- `types.ts`：`Proposal` / `NoteOutline` / `RetargetKind`。108 → 67 行。
- `api.ts`：`propose` / `apply` / `outline` / `retarget` 四个端点。202 → 160 行。**`snapshots` 夹在 `apply` 和 `rollback` 中间，别一起切掉。**
- `styles.css`：`.sp-target` / `.sp-ack`。`.sp-preview` / `.sp-where` / `.sp-warn` / `.sp-fold` 仍被审批面板用着，保留。

合计 -420 行 / +3 行。

## 没删什么

后端 `/v1/writeback/propose`、`/retarget`、`/apply`、`/outline` 四条路由原样保留——`web/` 客户端还在用，且将来插件若要恢复「先看提案再写盘」的形态，服务端不用重做。

`doApprove` / `doRollback` / `doRedo` / `revealInsert` / `saveOpenNote` 全部活着，人批与快照回退链路未动。
