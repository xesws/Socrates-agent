# 点读笔大方向改进方案

> 执笔：Kimi（复审总评）。依据四路并行功能审核（诊断舱、点读笔界面、后端与安全、总评），只定方向，不改产品代码。日期：2026-08-14。

## 为何现在动、动哪里

先说结论：点读笔的骨架是对的。框选、就地问、确认后写回、本地诊断，这条链路已经能跑通，四路评审对这一点没有分歧。现在要动，不是因为哪里塌了，而是因为三处结构性问题再不解，后面的活会越堆越歪。

第一处，诊断数的是「问了几遍」，不是「懂没懂」。`diagnose.aggregate` 只会按 hits 加权重排序（`CHIP_WEIGHT` 里 explain_zero 算 2 分、socratic 算 1 分，`WEAK_MIN_HITS = 2`），同一道题同一次坐下追着问三遍，报告里就是「高频薄弱」——可那明明是一节课正在消化，不是弱。第二处，演示路径经不起演示。默认芯片是只给反问的 socratic，负责讲透的 explain_zero 排在第二；侧栏 PenPanel 的 mermaid 和代码高亮没做完，师傅给的图在侧栏里是源码；最要命的是会话躺在内存里（`SessionStore._items`），页面一关、一切到诊断面板、一写回、一刷新，前端就拿着死掉的 session_id 去吃 404，演示当场死。第三处，后端还是演示代码的底子：会话和写回提案（`_proposals`）都在 RAM；apply 用的是 propose 时算好的旧行号，文件中途被动过就插错位置（stale line apply）；rollback 是「恢复最新快照」而不是「撤销这次写回」；`MAX_TOOL_ROUNDS = 50` 的工具循环能把服务器摁住；search 芯片真发过去吃的是一个裸 400。

为什么是现在？因为每一天真实使用都在丢数据。会话一断，追问的上下文就断了；writeback 的 apply/rollback 根本没进 `trajectory` 的事件流，`ts`、`ok`、`has_substantive` 记了却没人用。掌握度模型迟早要建，建的时候就会发现最值钱的证据——哪次问完沉淀了、哪次问完又回头问——在过去几个月里全被扔了。早一个月把事件流接上，就少一个月的瞎账。

动哪里：演示闭环、诊断模型、后端地基，三条线，多了不排。不动哪里：sandbox/快照/lint/diff 这条写回流水线、确定性索引、诚实挂起的 search、`.pen` 本地隐私——这四样是评审确认过的好东西，谁也别手痒。

## 三条主线（只保留三条，每条：现状、目标、不做、验收）

三条线有先后。**先动主线一**，理由三个：它是 demo-risk，演示当场死是最贵的失败，而产品正处在要给人看的阶段；它的活有边界，一个季度收得掉；它的会话落盘和事件续命恰好是主线二要读的「数据脊梁」——先把脊梁接上，后面才有米下锅。主线二是长期学习的魂，排第二不是不重要，是重要但不挡路。主线三贯穿始终，只做点名的事，防止镀金。

### 主线一：点读演示闭环与会话续命（demo-risk，先动）

**现状。** 演示路径默认落在 socratic 上，读者拿到的只有提示卡加一个反问，想把一段讲透得自己想到去点 explain_zero。PenPanel 的 mermaid 和高亮渲染是半成品。会话是纯内存对象，关闭面板、切诊断、写回确认、浏览器刷新，任一动作都会让会话消失。

**目标。** 演示脚本「框选 → 反问 → 讲透 → 写回」一气呵成，中途任何刷新和切换都不断片。具体三件事：会话落盘到 `.pen/sessions/`（append-only JSONL 就够，别上数据库），前端把 session_id 存 localStorage，重开页面能续上 messages 和 last_anchor；写回 apply 之后前端复用原会话而不是新建；PenPanel 的 mermaid 和代码高亮做到「能看」，和正文阅读器共用同一套渲染依赖。

**不做。** 不做账号、云同步、多人协作；不重写正文阅读器；mermaid 只渲染不编辑，不做导出图片；不做移动端；不为了演示效果去改手册内容本身。

**验收。** 同一条演示脚本连跑三遍不翻车：框选 → socratic 追问 → explain_zero 讲透（侧栏 mermaid 渲染成图）→ 写回确认 → 刷新浏览器 → 会话还在、锚点还在、再追问一句模型还记得上文。杀掉后端进程重启，会话照样续得上。

### 主线二：诊断从「计数」到「掌握度」（长期学习的魂）

**现状。** `aggregate` 的输入是 `trajectory.load_turns` 的 JSONL，输出是计数排序。它看不见的东西比看得见的多：时间戳记了没人用，所以分不清「同一次坐下的三连问」和「隔一周又回来问」；`ok=false` 的失败没人用；writeback 不是事件，「这道题我已经沉淀进手册」这个最强的学会信号系统看不见；从没被问过的 Q 不在任何桶里，盲区连名字都没有。

**目标。** 先把事件流补齐：同一 session 内、间隔小于阈值的连续追问归并为「一次学习事件」；writeback 的 propose/apply/rollback 写进 trajectory；工具循环失败记为信号。然后给每个 atom（`kind|level|title`）一个状态机：未探索 → 问过 → 追问中 → 讲通过 → 已沉淀。同一次坐下的重复问只推进状态，不叠加计数；从未触碰的关卡单独列「未探索」清单，不算弱也不算会。`narrate` 的输入从计数表换成状态表加证据条数。

**不做。** 不做间隔重复调度，那是 Anki 的活，是另一个产品；不打分数、不做掌握度小数、不做排名和分享——诊断是读者自己的镜子，不是成绩单；不上花哨可视化，状态列表加每关一行就够。

**验收。** 用构造场景说话：同一会话对同一 Q 连问四次，报告里它是「追问中」而不是 top weak；explain_zero 之后不再追问的进「讲通过」；writeback 成功的进「已沉淀」；整关没碰过的 Q 出现在「未探索」；narrate 的评语不再出现「你问了四遍所以薄弱」这种话。

### 主线三：写回安全与服务韧性（工程地基，贯穿）

**现状。** 提案和会话一样在 RAM，重启全没；apply 锚的是 propose 时的 start_line，期间文件被外部编辑器动过，行号漂了照样插；`snapshots.rollback` 恢复的是最新快照，连续写回两次想只撤第一次，没门；工具循环在一次请求里最多五十轮 LLM 调用，期间其他请求跟着排队；search 芯片灰着，但真发请求过去是裸 400 而不是一句人话。

**目标。** 四件事，件件有边界。提案随会话一起落盘，重启不丢。apply 之前重校验：比对文件 mtime 和行数，漂了就用确定性索引重算插入点，重算不出就带原因明确拒绝——宁可拒，不可插错。rollback 升级为「撤销指定的那次写回」：快照和 proposal 事件挂钩，按次撤销，「恢复最新快照」降级为兜底入口保留。工具循环加两道墙：总时长墙加每轮预算，超限就把已读到的材料收尾成一段文字回复，而不是继续转或者卡死。search 在前端永远不可点，后端万一收到，返回「P2 才开放」的正常答复。

**不做。** 不动 `insert.py` 的折叠块校验、unified_diff、`gitops.commit` 这条写路径本身——它是好的；不动 `index.py` 的确定性索引；不做向量检索，search 继续保持「诚实未开放」直到真有联网；不上 Postgres、Redis、Docker 编排；不做鉴权，这是本地单人工具。

**验收。** 三个对抗场景：外部编辑器把手册改了二十行再 apply，系统要么重定位成功要么带原因拒绝，绝不插错行；连续写回两次，能精确撤销其中任意一次且另一次不受影响；构造一个工具死循环，服务在时长墙内返回可读收尾，并发请求不被拖死。

## 明确不做

这一节和三条线里的「不做」同样有约束力，省下的是将来吵架的功夫。

已有的好东西，不动：sandbox/快照/lint/diff 写回流水线、确定性索引、诚实挂起的 search、`.pen` 本地隐私。这四样是产品的信用，动了等于拆地基搞装修。

新东西，不造：账号体系与云端同步；多人协作与分享；打卡、积分、勋章等任何形式的激励系统；掌握度分数与排名；向量数据库与联网检索（P2 之前）；移动端与浏览器插件；mermaid 编辑器；插件体系与配置中心。也别开「顺手美化一下 UI」「补个 README」这种支线——除非它挡在三条主线的验收上，否则一律排到主线之后。

## 建议顺序（季度级，不是 sprint 清单）

**Q1：主线一全部，加主线三的两小块**——提案落盘、search 友好拒绝，因为这两块正好压在演示路径上。季度出口：演示脚本三遍不翻车，杀进程重启会话还在。

**Q2：主线二全部，加主线三的事件流补齐**——writeback 事件进 trajectory 是两条线的接缝，必须同季做，否则状态机永远缺「已沉淀」这一档。季度出口：四个构造场景的诊断验收全过。

**Q3：主线三剩余部分**——stale line 重校验、按次撤销、工具循环墙。排最后不是因为它轻，是因为写回是低频动作且有快照兜底，炸不到演示；但这季必须收，手册越写越厚，漂移的概率只会越来越大。季度出口：三个对抗场景全过。

每季末尾留一周「只删不加」：把这一季为赶验收留下的临时代码清掉，不立新功。

## 做成之后系统变成什么

现在的点读笔，是一支会聊天的荧光笔加一个计数器：演示靠运气，诊断靠猜，写回靠赌行号没变。

做成之后，它是一支记得事的笔：记得你读到哪、哪道题追问了三次才通、哪道题已经沉淀回手册、哪些关还没碰。演示路径无聊地稳定——「无聊」在这里是褒义词，演示不该有悬念。诊断从「你问了几遍」变成「你卡在哪、通了没、沉淀了什么」。写回从「赌」变成「变了就明说」。

它仍然是本地的、单人的、诚实的：search 没开就说没开，诊断不给分数，数据不出 `.pen`。这三条不是限制，是这支笔和一堆「AI 学习平台」的区别。
